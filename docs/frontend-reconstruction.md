# LAST KICK 前端重构

当前表现使用 **PixiJS + GSAP + Vite / Rolldown + 视频基底**。球场、球员、球路和扑救动作由 MP4 呈现；比分、选路、报价和控制由 Pixi 绘制。Provider 继续决定结果，媒体不会影响成功率。主入口不加载 PlayCanvas。

## 开场与动作

开场直接播放 Seedance CG，结束后进入首球。已删除标题、英文标语、倒计时、进度条和覆盖渐变；只有无文字的跳过图标。减弱动态效果时跳过开场和待机循环，用户主动触发的射门仍播放真实视频。

每球按 `goal/save-球路-门将方向` 选择已验收视频。十二种攻防结果映射到七种动作组合，方向均以射手视角为准。`goal-L-R` 已通过球路与动作审看，但观众动态还未通过。最新制作计划为七条带动态看台的动作视频（包括重做该样片）及一条 8 秒待机视频，**当前尚不能完整进行一场视频比赛**。推射和抽射现阶段共享同方向结果的画面，不声称已有不同射法动作。

缺片时在调用 Provider 之前停止本球提交；没有消耗球次、改比分、改返还或产生结果。待机观众动态及成功／失败两条视频的观众反应均需通过审看，两条匹配视频还须下载成功，之后才允许提交。已删除缺片时的文字结果替代以及覆盖动作的大字提示。发生实际播放中断时保留已接受结果，支持用回放重看同一视频。

动态待机采用正常向前播放的完整视频，不倒放拍手、旗帜或人群起立。验收分别观察看台不同区域：近排手臂与身体姿态应实际变化，分组起立、挥旗、拍手有不同节奏；结果时出现与球网或手套接触相配的观众反应。当前旧待机仅作为临时画面，不标为动态观众成片。`tools/import-stadium-loop.py` 和 `tools/import-shot-clip.py` 只有显式提交动态观众审看记录后才更新生产清单；旧 CG 提取工具不能覆盖已验收的动态待机。

视频触球与结果音由 `requestVideoFrameCallback` 的媒体时间驱动，不支持该 API 时使用 `timeupdate`。回放不调用 Provider。每条视频带 poster，缓存只保留最近四条动作，销毁时释放 Blob URL。手机素材使用保全球门的 4:3 裁切加同源模糊上下填充，属于横片适配，不是原生竖屏拍摄。

## 现场声音

声音默认开启，首次点击进入球场后建立 AudioContext。近处为双拍心跳和真实男性呼吸，远处为立体声观众呼喝、鼓掌及欢呼；看台具有延迟反射，呼吸保持干声。已删除合成低吟和旋律。

心跳常规约 78–92 BPM，开场 94 BPM，提交准备时约 104–118 BPM。关键球提高心跳与呼吸强度；实际触球时压低这两层及节奏，结果时播放录制的观众反应。鼓点与分散拍手走独立节奏。静音停止排程和声源，切到后台暂停，恢复时不会追放积压节拍。声音不申请麦克风权限。

三段实录来自 Freesound 的 CC0 素材，按原始网页公开的高清预览地址取得，处理包括滤波、音量归一化、首尾淡化和 MP3 打包。来源与作者见 `asset-credits.md`。试听导出使用与比赛完全相同的 Web Audio 图，文件为 `previews/stadium-live.mp3`。

## 验证与开发

`npm test` 检查规则、单次提交、报价锁、缺片或未验收看台不提交、媒体下载失败重试、回放隔离和动作映射。`npm run verify:assets` 检查清单文件、已批准动作映射、音频和 HTMLPreview 经典脚本。动作包标记为 complete 时要求七种组合覆盖及待机／动作看台均通过审看。

开发模式 `?audio-preview=1` 导出 24 秒 WAV；`?clip-preview=1` 可在实际视频场景中审看已批准射门并保留终帧，不调用 Provider。审看按钮位于画面外，开发工具不进入生产包。浏览器证据见 `browser-qa.md`。
