# LAST KICK 前端重构

当前比赛表现采用 **PixiJS + GSAP + Vite / Rolldown + 视频基底**。球场和人物来自已经完成的 Seedance CG，比赛判定继续来自原有 Provider。实时 3D 源码保留为实验参考，主入口不再加载 PlayCanvas。

## 运行结构

| 模块 | 职责 |
| --- | --- |
| VideoMatchScene | 写实待机视频、海报兜底、攻防阶段、依据结果选择动作短片 |
| VideoBase | 内联静音视频、视频时间回调、中断释放、拒播恢复、末帧保持 |
| PixiJS 8 | 比分、方向目标、射法、报价、情报、返还、结果反馈 |
| GSAP 3 | 加载、开场字幕、倒计时与 UI 转场 |
| MatchController / LocalProvider | 单次提交、报价冻结、比分与结算；媒体不能决定结果 |
| StadiumAudio | 整场重鼓、群体拍手、原创无词低吟、关键球变奏、击球及欢呼 |
| Vite 8 / Rolldown | 单个 IIFE 构建；同时支持普通部署和 HTMLPreview 的经典脚本注入 |

## 视频比赛的状态

已接入：Seedance 写实开场、同源待机循环、横竖屏海报与适配、真实加载动画、跳过、倒计时、完整操作界面、整场声音。待机是开场前 0.85 秒的正反拼接，共 1.75 秒，不包含射门结果。手机待机使用保全球门的 4:3 裁切加同源模糊上下填充，保留三个方向；不是原生竖屏生成。

**动作包尚未齐备**。生产清单只接受 `status: approved` 的短片。缺片时暂停待机，显示实际判定及制作提示，再恢复下一阶段；不会用一条进球短片代表扑救，也不会跳回卡通模型。旧卡通庆祝已从播放清单移除。

动作键为 `goal/save-球路-门将方向`。球路与门将方向由已有确定性编排从权威结果推导，所有方向按射手视角。攻防十二种结果会映射到七种不同球/门将组合；左右镜像或射法复用必须在验收后标明处理方法，不能未经检查扩大覆盖率。

只有拍摄好的比赛机位可用；任意实时镜头旋转与自由曲线球路需要另外的 3D 系统。回放播放上一条结果，禁止再调用 Provider 提交。

## 声音

点击进入球场后才建立音频播放。默认声音开启，顶部可静音；静音立即停止所有声源和排程，重新开启恢复当前比赛，切到后台暂停。常规 108 BPM、开场 116 BPM、关键球 124 BPM。两次重踏加群体拍手，四小节变化的九声部低吟；出脚前压低节奏层，击球与观众结果音独立混音。动态压缩器控制瞬态。

试听导出与线上使用同一个 Web Audio 引擎，不访问麦克风。开发模式 `?audio-preview=1` 可导出 24 秒 WAV；仓库保存了 MP3 试听。低吟是合成的原创无词动机，后续可换用真实录制的人群声部。

## 恢复与验证

视频拒播、网络失败、超时、中断不改变已接受的结果；控制器在呈现后提交新状态。音效触发依据视频 `currentTime`，不会靠固定墙钟提前宣布进球。尚缺视频时只显示判定提示。

`npm test` 检查数学规则、单次提交、旧报价冻结、媒体失败、回放隔离和动作映射。`npm run verify:assets` 检查经典脚本解析、清单资源存在与已批准动作。`npm run build` 生成部署包与仓库 HTMLPreview 入口。真实浏览器验收见 `browser-qa.md`。
