# LAST KICK 前端重构

本次在已有 S0/S1 结算与玩法上重建表现层，落实 PixiJS + GSAP + Vite，并按最新需求加入 PlayCanvas 实时 3D。比赛画面由实时场景驱动；开场和赛后庆祝使用视频基座。

## 技术分工

| 模块 | 实现 | 职责 |
| --- | --- | --- |
| 实时比赛 | PlayCanvas 2 | 球场、球门、球网、球员 GLB、骨骼姿态、足球与机位 |
| 游戏界面 | PixiJS 8 | 比分、球次、球门选区、射法、方向报价、返还、情报、结果反馈 |
| 动作衔接 | GSAP 3 | 助跑、踢腿、弧线飞行、扑救、落地、球网反应、镜头切换 |
| 游戏外壳 | MatchController | 单次请求锁、旧报价冻结、接收结果、动画后切换阶段 |
| 权威结果 | 已有 OutcomeProvider / LocalProvider | 报价、成功判定、比分、门将记忆和结算 |
| 视频基座 | VideoBase + media-manifest.json | 横竖屏开场、庆祝、首帧海报、按需加载与播放失败恢复 |
| 工程构建 | Vite 8 / Rolldown | npm 开发、生产包、HTMLPreview 入口与 Pages 构建 |

赛场与控制区都在画布中绘制。HTML 保留导航、说明/战报弹窗、读屏器状态，以及与画布控件一一对应的透明语义按钮。球员、足球与球门不再由 DOM/CSS 图形模拟。

## 实时 3D 与视频的边界

射门、扑救与单球回放均运行同一套实时 3D 编排。跟随镜头自动切换攻防视角，另有转播与门后机位；球门目标通过世界坐标投影到 Pixi，不会因机位变化选错球路。所有方向以射手视角为准。

成功判定来自 `RoundResolution`，动画不能反向决定比分或派发金额。现有契约没有实际门将扑向、对手射向和失误细分类，因此表现层使用确定性的结果编排：扑救时球与门将动作接触，进球时球进入球网。它没有添加第二套结果随机数。以后若服务端增加这些细节，应直接用下发值替代编排分支。

当前球路为随时间变化的 3D 曲线，人物采用带骨骼 GLB 的程序姿态与动作衔接。它不是刚体物理或完整动作捕捉系统。该方式便于先保证方向、时序与结算一致，再升级球员模型、动作片段或物理细节。

视频只承载不依赖所选方向的开场和赛后庆祝，庆祝片不重演一脚不同方向的射门。开场已替换为经过检查的 OpenArt / Seedance 2.0 写实短片；庆祝仍使用实时球场录制。单球回放重新播放上一条结果的动作，禁止调用 `submit()`。

## 媒体与布局

- 开场：横屏 1280×720，竖屏 720×1280（从同一原片居中裁切），24 fps，H.264、无音轨。开场期间覆盖整个比赛区域，包含字幕、跳过和 3—2—1 倒计时；最后一帧保留至倒计时结束，随后接入实时比赛。
- 庆祝：横屏 1280×720，竖屏场景窗口 720×960（3:4），24 fps，H.264、无音轨；竖屏控件位于场景窗口下方。
- 每条短片配首帧 WebP；清单记录时长、分辨率、编码与资源路径。
- JS 加载前先显示轻量入场标识；场景初始化显示聚光、旋转足球及真实加载阶段进度，完成后渐隐。首屏先加载模型、球衣与本地字体；大厅显示 Seedance 首帧，开场只预热 metadata，庆祝在需要时加载，不预下载所有短片。
- 开场可跳过。播放被阻止、文件错误、超时或横竖屏变化时立即恢复实时场景，释放交互锁。
- reduced-motion 模式跳过开场/庆祝，并加快必须表达结果的动作。
- 默认静音；点击顶部声音按钮后启用观众氛围、开场鼓点、哨声与触球音。声音不参与结果计算。
- 桌面保留右侧比赛中心；竖屏收起情报栏，通过弹窗查看完整倾向及样本数量。

## 保留的玩法深度

三种门将原型、赛前倾向、带衰减的本场方向记忆、关键球提示、推射/抽射、双分支返还、攻防交替、提前终局、限定骤死、收钱窗口及战报均来自原有模型。界面将这些信息放在决策时可见的位置。

阵容构筑、教练调整、压力机制和快速模式仍属于后续阶段，未在此次重构中加入未经数学验证的规则。

## 运行和构建

```sh
npm ci
npm run dev
npm test
npm run verify:math
npm run build
npm run preview
```

开发地址为 `http://127.0.0.1:5173/`。测试 seed 仅在开发模式通过 `?seed=...` 指定。生产构建忽略该参数。

`dist/index.html` 为部署入口；`dist/standalone.html` 内联生产 JS/CSS。仓库根的 `standalone.html` 支持 HTMLPreview 从相同分支读取 `public/assets`。模型、字体、视频按清单外置加载，因此应通过 HTTP 打开，不宣称可单独离线运行一个 HTML 文件。

CI 验证单元测试、状态求解、无损区间、蒙特卡洛与生产构建，并保存 `penalty-preview` 静态包。重构分支和 PR 仅运行检查；原功能分支或明确手动运行才部署 Pages。

## 媒体再制作

开发模式打开 `?capture=1`，使用录制按钮生成 WebM。分别在桌面与竖屏窗口录制开场、庆祝，保存下载文件后执行：

```sh
python -m pip install imageio-ffmpeg
python tools/bake-media.py intro-landscape.webm --name intro --orientation landscape
```

该脚本输出 MP4 和首帧 WebP，并更新清单。正常 npm 构建使用已提交的媒体，无需 Python 或 FFmpeg。`tools/prepare-kits.js` 从可编辑 SVG 重新生成球衣贴图；源模型来自 Kenney 角色包，经 FBX2glTF 转换后提交 GLB。

已生成并检查的 Seedance 原片可用 `python tools/import-seedance.py path/to/source.mp4 --history-id KQ9mego53d8bOcrD0Ur8` 重新压缩横竖版本、提取海报并更新清单。该脚本不调用生成 API，也不产生新的生成费用。实时录制脚本用于制作备用片或庆祝片，避免覆盖正式 Seedance 开场。

已在 Windows 修正数学检查脚本的入口判断，避免原 `file://` 字符串比较导致本地执行不运行检查。数学公式与参数保持原实现。状态求解覆盖 1,850,400 个状态；无损检查覆盖 97,020 个收钱窗口、2,141,208 个动作；每策略 20,000 场蒙特卡洛回归通过。
