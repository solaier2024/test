## 0. 承重墙：EV 中性原则（与拳击方案一致，不重复论证）

**深度不等于"技术好的玩家赢更多钱"。** 玩家掌控的是**波动形态与会话节奏**,不是期望值。理由三条（RTP 需认证、SEGOB 事前审批、在位产品共识）已在拳击方案 §0 详述,此处不再展开。

本文每个系统都标注 EV 中性的实现方式。**实现时不要为了"手感"破坏它。**

---

## 1. 为什么点球比拳击更适合做深度

这是本方案的立论基础。点球大战的真实赛制自带三层结构,是拳击没有的：

| 维度 | 拳击（12 回合 ladder） | **点球大战** |
|---|---|---|
| 结构 | 单向连胜,一条线 | **交替攻防,有比分** |
| 角色 | 只当拳手 | **既当射手又当门将**,两种技能表达 |
| 情境 | 每回合情境相同 | **比分决定每一脚的意义**（2-0 领先可求稳,0-2 落后必须冒险） |
| 赛制 | 自定终点 | **5 轮 + 骤死赛**,真实赛制自带高潮 |
| 心理 | 玩家 vs 系统 | **读心博弈**（门将猜射手,射手骗门将） |

**最关键的一条**：点球大战里「比分」是一个与倍率正交的状态变量。同一个射门区域选择,在 2-0 领先和 0-2 落后时价值完全不同 —— **这种情境依赖是纯 ladder 游戏在结构上不可能拥有的深度**。在位的 7 款足球即时赢产品（Evoplay 5 款、InOut 2 款）**全部没有比分概念**,只有连续命中次数。

## 2. 核心循环

```
选阵容与罚球顺序 → 5 轮交替攻防 →（平局则骤死赛）→ 结算
  每轮：【进攻】读门将站位 → 选区域+力道 → 视频 → 结果
        【防守】读对手倾向图 → 选扑救方向+出击时机 → 视频 → 结果
        → 比分更新 / 压力更新 / 倍率更新 → [收钱 | 继续]
```

### 2.1 会话时长的取舍（必须正视）

两阶段设计让单轮约 12–14 秒,整场 5 轮约 60–90 秒 —— **明显长于 Evoplay 点球的单局 10–15 秒**。这是"深度换时长"的真实代价,不掩饰。

**对冲方案：双模式,同一数学内核,同一 RTP。**

| 模式 | 结构 | 单局时长 | 目标用户 |
|---|---|---|---|
| **快速模式** | 只罚球,门将阶段自动结算（显示结果不需操作） | 20–30 秒 | 想要即时赢快节奏的用户、首次上手 |
| **完整模式** | 攻防双阶段全手动 | 60–90 秒 | 追求深度的用户、老玩家 |

两个模式共用 `shootout-math`,RTP 完全一致（自动结算用相同 PRF 分支,只是不暴露选择权）。这同时也是**新手引导的天然梯度**：先快速模式上手,再解锁完整模式。

## 3. 深度系统（六层）

### 3.1 交替攻防与比分 —— 结构性深度 ★ 方案的心脏

每轮玩家罚一球、守一球。比分独立于倍率存在。

- **进攻**：7 个区域（左上/中上/右上/左下/中下/右下 + 吊射 Panenka）× 2 种力道（推射 placed / 抽射 driven）
- **防守**：扑救方向（左/中/右 × 高/低）+ **出击时机**（提前扑 = 覆盖范围大但容易被看穿；等一拍 = 范围小但反应真实）

**比分如何创造深度**：
- 领先时,保守选择（推射中下）的低波动是有价值的 —— 因为你只需要不输
- 落后时,必须选高波动（抽射角落/吊射）—— 因为求稳等于输
- **这让"该选哪个区域"有了一个随局势变化的正确答案,而不是永远相同的随机猜测**

**EV 中性**：所有区域×力道组合的 `命中率 × 倍率步进` 恒等。比分只改变**哪种波动对玩家有利**,不改变任何选项的期望值。

### 3.2 压力系统（Presión）—— 双向、反应式的路径依赖 ★

替代拳击的体力系统,但更好,因为**它是双向的且由比分驱动**。

压力上升：落后、第 4/5 轮、刚罚失、客场作战
压力下降：罚进、扑出对方点球、领先

高压下：**抽射/吊射的命中率下降,但倍率步进同比上升**（EV 中性的变波动器,与拳击体力同一机制）；推射受影响较小。

**为什么比体力系统更好**：
- 体力是单调递减的（只会越来越少),压力是**可恢复、可逆转**的 —— 这创造了"势"的概念
- 压力由比分驱动,所以它**把 §3.1 的比分系统和倍率系统耦合起来**,两个系统互相放大
- 真实的点球大战恰恰就是一场压力管理,机制与题材完全同构（不是硬套）

**路径依赖**：第 2 轮的罚失会抬高第 3–5 轮的压力。一局形成不可逆的"心理曲线"。

### 3.3 门将记忆与倾向图 —— 读心层 ★ 最具差异化的设计

**这是在位 7 款竞品全都没有的机制。**

**你进攻时**：AI 门将**记住你这场用过的区域**。重复使用同一区域 → 门将猜中概率上升。你必须主动变化。
**你防守时**：屏幕显示对手的**倾向图**（一张 7 区热力图,标注他已罚过的位置与次数）。读图告诉你该往哪扑。

**EV 中性实现**：门将的"读"同时改变命中率与倍率步进（反向）。重复一个"已被盯上"的区域 = 命中率低但赔付高。**所以"变化"与"重复"长期等价,只是波动不同。**

**为什么这是最好的深度层**：它是**信息深度**,不是操作深度。玩家得到的是真实可用的信息（倾向图),做出的是有依据的判断,而不是在猜随机数。而信息深度不花时间 —— 看一眼热力图是 0.5 秒的事。这正好符合 §2.1 的时长预算。

### 3.4 阵容与罚球顺序 —— 赛前构筑层 ★ 零局内时间成本

开赛前从球员池里选 5 名罚球手并**排定顺序**。每人有特质：

| 特质 | 效果 | 最佳位置 |
|---|---|---|
| **神射手 Francotirador** | 推射命中率高、步进小 | 任意,稳定收益 |
| **重炮 Cañonero** | 抽射步进大、命中率低 | 领先时使用 |
| **冰血 Sangre Fría** | 不受压力影响 | **第 5 轮**（压力最高处） |
| **艺术家 Artista** | 吊射特化,高波动 | 骤死赛 |
| **门神 Portero** | 守方加成（每局选 1 名门将） | — |

**顺序决策是真正的策略**：因为压力在第 4/5 轮最高,把"冰血"放最后是对的；但如果你打算在第 3 轮就收钱,那把他放第 5 轮就是浪费。**赛前决策与会话计划耦合**,这是 roguelite 式的构筑深度,而且**完全不占局内时间**。

**EV 中性**：特质重新分配 5 轮之间的波动,不改变整局总期望。

### 3.5 骤死赛与"双倍罚球" —— 高波动尾部

5 轮打平进入骤死赛：每轮单回合定胜负（你罚进 + 对手罚失 = 赢；你罚失 + 对手罚进 = 全失）。

另外在任意决策点提供**双倍罚球**（Penal Doble）：把已累积倍率押在单独一脚上,命中翻倍、罚失归零。

这是调研报告里 lucha de apuestas「加倍或全失」机制的足球本地化版本,给追求极限波动的玩家一个出口,而不污染主循环。

### 3.6 赛事情境与本地化 —— Liga MX 语境 ★ 竞品空白

调研报告的核心发现之一：**在位产品全是"泛国际足球"或"巴西街头足球",没有一款是墨西哥语境的。**

- **杯赛进程**：连续多场点球大战组成淘汰赛,逐轮对手更强（门将记忆更准、倾向图更隐蔽）
- **主客场**：客场作战 = 基础压力更高 = 波动更大（EV 不变）
- **语境资产**：墨西哥西语解说（非欧洲西语）、Estadio 氛围声浪、三色旗元素克制使用、经典德比对阵氛围

### 3.7 评估后排除的

| 候选 | 为什么不做 |
|---|---|
| 真实时机判定（按住蓄力条打点） | 违反 EV 中性；且 SEGOB 过审风险高 |
| 真人 PvP | 价值高,但应作为 **M6 之后的独立增量**,首作不做以免摊薄范围（见 backlog `X-5`） |
| 11 人全场比赛模拟 | 偏离即时赢品类,时长失控 |
| 每轮换门将 | 与阵容层重叠,增加操作负担 |

## 4. 胜利条件（四条路径,EV 相同、波动递增）

| 路径 | 触发 | 回报 | 波动 |
|---|---|---|---|
| **收钱** | 任意轮后主动 | 当前累积倍率 | 低,玩家自定 |
| **赢下大战** | 5 轮比分领先 | 累积倍率 × 胜利加成 | 中 |
| **完美大战** | 5/5 全进 + 扑出 ≥3 球 | 累积倍率 × 完美加成 | 高 |
| **骤死胜 / 双倍罚球** | 骤死赛取胜或双倍命中 | 极高倍率 | 极高 |

倍率随**每个进球**与**每次扑救**累积 —— 这让防守阶段有真实收益,不是走过场。

典型张力点：*"2-1 领先,还剩 2 轮,现在收 3.2x,还是推到底拿胜利加成的 6x?"*

## 5. 一局示例（走通全部系统）

```
赛前：阵容 [神射手, 重炮, 神射手, 艺术家, 冰血]  客场（基础压力 +15）
      对手门将：反应型

R1 攻 推射左下   进  比分 1-0  压力 10  倍率 1.30x
   守 扑右       扑出! 比分 1-0  压力  5  倍率 1.70x   ← 扑救也加倍率
R2 攻 抽射右上   进  比分 2-0  压力  0  倍率 2.45x
   守 扑左       进球 比分 2-1  压力 10  倍率 2.45x
R3 攻 推射左下   被扑! 比分 2-1  压力 30  倍率 2.45x
        ↑ 门将记住了 R1 的左下 —— 重复区域被盯上
   守 扑中       扑出! 比分 2-1  压力 20  倍率 3.10x
R4 攻 吊射(艺术家) 进 比分 3-1  压力 10  倍率 4.40x
   守 扑右       进球 比分 3-2  压力 20  倍率 4.40x
   ── 决策点：收 44 MXN？还是打 R5 争胜利加成？
      冰血在 R5（不受压力影响）→ 赛前的排序决策在此兑现
R5 攻 推射(冰血) 进  比分 4-2  → 赢下大战  倍率 4.40x × 1.8 = 7.92x
```

R3 的失败是**玩家自己造成的**（重复了 R1 的区域,被门将记住）。R5 的成功来自**赛前的排序决策**。这两点就是深度的证据 —— 局面由玩家的历史选择塑造,不是系统随机抛出的赌局。

## 6. 数学内核与 EV 中性落地（沿用拳击方案架构）

`shootout-math`：**纯函数式、零依赖、Node 可运行**,要求与拳击方案一致：

1. 脱离浏览器可跑（为了蒙特卡洛）
2. 完全确定性（同 seed + 同决策路径 → 同一场比赛）
3. **将来可原样搬到服务端**

**RTP 模拟器**必须验证的策略集（比拳击更多,因为决策面更大）：

- 全推射 / 全抽射 / 全吊射
- 固定区域（永远左下,测门将记忆的惩罚是否 EV 中性）
- 完美轮换（永不重复区域）
- 定轮收钱（R1/R2/R3/R4 各一组）
- 永远打满 / 永远进骤死
- 快速模式 vs 完整模式（两者 RTP 必须一致）
- 各阵容特质组合

**全部策略 RTP 须落在 ±0.3% 同一容差带** —— 这是 EV 中性的自动化证明,进 CI 做门禁。

## 7. 实现架构（与拳击方案同构,不偏移）

```
┌─ 表现层  Pixi + 视频播放器 + GSAP            零游戏逻辑,可整层替换
├─ 游戏外壳  轮次状态机 / 攻防阶段机 / UI 状态 / 资产调度
├─ OutcomeProvider（接口）  ←──────── 服务端接入的唯一切换缝
│    ├─ LocalProvider   阶段一：本地 seed + 本地 PRF
│    └─ RemoteProvider  阶段四：服务端 seed + commit/reveal
└─ shootout-math（纯 TS,零依赖,全单测 + 可模拟）
     ├─ PRF / 带种子 RNG
     ├─ 压力、比分、门将记忆、阵容特质模型
     ├─ 赔付表与倍率阶梯
     └─ RTP 蒙特卡洛工具
```

### 7.1 PRF 决策树（与拳击方案完全一致）

所有随机性由 `PRF(seed, 轮次, 阶段, 决策路径)` 导出。决策路径现在包含**攻防两个阶段**与**赛前阵容顺序**。

- 下注时服务端生成 seed `S`,下发 `hash(S)` 承诺
- 玩家选择决定读取哪条随机分支,无法影响分支内数值
- 终局揭示 `S`,客户端可校验并完整重放
- **阶段一本地生成 seed,用完全相同的 PRF；接服务端时只需把 seed 生成与承诺移到服务端 + 加揭示校验,`shootout-math` 与表现层零改动**

**注意点**：阵容顺序是赛前决策,必须纳入决策路径的哈希输入,否则玩家可以在看到结果后反悔重排。

### 7.2 现在就要冻结的数据契约

- **`ShootoutConfig`** —— 赔付表、压力曲线、7 区命中率基表、门将记忆权重、球员特质参数、胜利/完美/骤死加成。将来由服务端下发
- **`RoundResolution`** —— 单阶段权威结果（是否进球/扑出、比分变化、压力变化、门将记忆更新、倍率变化、是否终局、终局类型）。客户端**只呈现,不计算**

### 7.3 ★ 生产约束：视频数量必须按「结果类别」而非「区域组合」收敛

**这是本方案最重要的一条生产决策,搞错会让资产成本爆炸。**

7 区 × 2 力道 × 3 结果 × 2 朝向 = **84 条视频**,不可接受。

参考平台的橄榄球游戏给出了正解：**它的视频是按结果类别组织的**（`touchdown` / `interception` / `sack` / `incomplete`),不是按"哪个球员往哪个方向跑"的组合。

点球照此收敛到约 **16 条主片**：

```
进球类   goal-corner.mp4   goal-center.mp4   goal-panenka.mp4   goal-deflected.mp4
扑救类   save-dive.mp4     save-reflex.mp4   save-panenka.mp4
打偏类   miss-post.mp4     miss-over.mp4
守方类   keeper-save.mp4   keeper-beaten.mp4
氛围类   bg-loop.mp4  intro.mp4  win-big.mp4  win-epic.mp4  win-perfect.mp4
```

每条配 `-land` / `-port` 两版（竖版重剪更短）+ 首帧 poster。区域差异通过**镜头机位 + Pixi 层叠的球轨迹特效**表达,不靠独立视频。

规格沿用参考平台实测值：H.264、**无音轨**、横屏 1280×720 @24fps、竖屏 720×540 @24fps、背景循环 8s @218kbps、`media-manifest.json` 驱动渐进加载、pixi-filters 按需 tree-shake。

## 8. 分阶段路线

| 阶段 | 目标 | 可验证成果 | 美术投入 |
|---|---|---|---|
| **M0** | 数学内核 + RTP 可证明 | 无美术调试 UI 可手玩完整一场,模拟器证明全策略 RTP 同带 | 0 |
| **M1** | 六层深度系统进内核 | 模拟器输出各策略波动画像；双模式 RTP 一致性验证通过 | 0 |
| **M2** | 表现层与视频基座 | Pixi 外壳 + 攻防阶段机 + 横竖屏 + 渐进加载（占位视频） | 占位 |
| **M3** | 资产管线 | 16 条主片产线跑通,命名对齐参考平台 | 正式 |
| **M4** | 服务端接入 | OutcomeProvider 切 Remote,commit/reveal 校验通过 | — |
| **M5** | 上线准备 | RTP 认证包、es-MX 本地化、负责任博彩、运营商对接 | — |

**排序逻辑不变**：M0/M1 零美术投入即可回答"深度是否真的有趣"和"RTP 是否稳",这是最大的两个不确定性。点球的决策面比拳击更大,**EV 中性的验证工作量也更大**,更不该在数学锁定前投美术。

详细任务见 [penalty-shootout-backlog.md](./backlog.md)。

## 9. 风险

| 风险 | 性质 | 应对 |
|---|---|---|
| 深度系统破坏 EV 中性 | **最严重** | 多策略 RTP 同带检验进 CI；决策面比拳击大,策略集需更全（§6） |
| 会话时长失控 | **高**（本方案特有） | 双模式对冲（§2.1）；单轮 ≤14 秒硬预算,超出即砍 |
| 玩家读不懂多层系统 | **高**（六层系统,认知负担大） | 快速模式作为引导梯度；比分/压力/倾向图常驻可见；分层解锁 |
