## 0. v2 修订记录（v1 的错误与修正）

评审稿指出的问题经逐条核对**全部成立**。其中三项是实质性错误,不是表述问题。

| # | v1 的错误 | 性质 | v2 的修正 |
|---|---|---|---|
| 1 | 用「命中率 × 倍率步进恒等」推导整局 EV 中性 | **数学错误** —— 只平衡了单次成功那一步,未纳入失败分支、终局、奖金与收钱权的价值 | 改用现金价值的鞅条件（§2.2）,对每个可达决策状态与每个合法继续动作成立 |

## 1. 产品方向与双层目标

保留五轮比分、交替攻防、主动收钱、可读对手。局内深度围绕 **观察对手 → 形成计划 → 对手调整 → 利用或改变计划** 建立。

玩家的目标分两层,**必须分别定义,不能混用**：

- **比赛目标**：进球、扳平、守住赛点、赢下大战。不同选择可以改变比赛取胜概率。
- **金钱目标**：选择符合自身偏好的兑现时机与收益分布。

关键区分（v1 在这里混淆过）：**比赛胜率提高不等于金钱期望提高；金钱波动增加不等于逆转概率提高。** 比赛胜率、赢钱概率、期望收益、收益方差是四个独立量,需分别定义与报告。

## 2. 结算模型与 EV 中性（v1 的核心修正）

### 2.1 EV 中性的定位：产品设计目标,不是监管要求

**"不同策略的金钱期望相同"是我们选择的数学目标**,涵盖玩家可用的公开信息、阵容、动作、合法调整、模式与收钱策略。

理由是产品与认证层面的：RTP 需可证明可认证；若策略间 EV 不同,最优策略的 EV 就定义了实际 RTP,其余策略成为陷阱。

**不再声称这是 SEGOB 的要求。** 实施条例第 85 条涉及线上、电话或电子接受投注的内控、记录与事前审批,**未规定每种玩家策略的 EV 必须相同**。监管立论与数学目标分开陈述。

### 2.2 正确的 EV 中性条件（鞅条件）

统一定义：

- `W` = 下注额；`r` = 目标 RTP；初始整局期望返还 `= W × r`
- `C(s)` = 状态 `s` 下**当前可兑现的现金价值**
- `G(s)` = 终局状态的实际返还
- 概率必须以**玩家决策时可见的信息**为条件计算

要求玩家在任一可兑现状态选择「继续」或「收钱」都保持相同 EV,充分条件是：

```text
对每个可到达决策状态 s、每个合法继续动作 a：

    C(s) = Σ P(s' | s, a, 可见信息) × C(s')

终局状态：

    C(s) = G(s)

初始状态：

    C(s₀) = W × r
```

后继状态的现金价值须包含后续收益、损失、终局与信息变化。**只平衡单次进球的概率与奖励不能替代这个条件** —— 这正是 v1 的错误所在。

RTP 定义为「实际返还 ÷ 下注额」,返还是否含本金在规则中明确。容差以**百分点**表达,不混用相对误差。

### 2.3 修复无损继续区间：现金价值必须可降

鞅条件有一个直接推论：**`C` 既然是鞅,就必须能下降。** 否则"继续"的期望恒大于当前值,收钱永远是劣选。

v1 的示例恰好违反这一点（失败不扣倍率 + 五轮内不会被淘汰 = 前两轮无损增值）。v2 的修正：

- **区分比赛比分与可兑现金额**,后者允许因结果下降
- 射门失败可以继续比赛,同时降低当前现金价值
- 对手进球影响比分,也可以降低当前现金价值
- 进球/扑救成功对现金价值的贡献,与失败分支**一起校准**
- 落败归零、平局返还等终局约束一并进入完整求解
- **HUD 显示当前可兑现金额**；潜在终局奖励单独标注,不混入当前报价

单步示例（当前现金价值均为 10 个货币单位,仅说明约束,非正式参数）：

| 选项 | 成功概率 | 成功后现金价值 | 失败后现金价值 | 单步期望 |
|---|---|---|---|---|
| A（推射） | 80% | 11 | 6 | 0.8 × 11 + 0.2 × 6 = **10** |
| B（抽射） | 50% | 14 | 6 | 0.5 × 14 + 0.5 × 6 = **10** |

成功率、收益分布与波动不同,单步期望相同。该示例未含比赛终局,不能直接作为正式参数。

**若配置无法同时满足现金价值鞅条件、落败归零、赔付上限与所有动作同 EV,必须修改规则或明确放宽数学目标,不能在界面继续承诺已经不成立的性质。**

### 2.4 验证方式：完整求解 + 蒙特卡洛回归

在有限状态、有限轮数下分别求最优与最差金钱策略：

```text
Vmax(s) = max { C(s), max_a Σ P(s'|s,a) × Vmax(s') }
Vmin(s) = min { C(s), min_a Σ P(s'|s,a) × Vmin(s') }

仅在允许收钱的状态加入 C(s) 选项；终局用 G(s)。
```

若鞅条件精确成立,则 `Vmax(s₀) = Vmin(s₀) = C(s₀) = W × r`。**这才是真正的证明** —— 列举策略的蒙特卡洛做不到。

状态需覆盖：比分、双方剩余罚球次数、阶段、现金价值、公开线索、记忆、压力等级、阵容、已用调整次数、模式。

> **重要衍生结论**：§3.1 的操作面缩减、压力离散为三级、记忆偏移设上限、骤死赛最多三组 —— 这些不只是体验与认知考虑,**更是让完整求解在状态空间上可行的前提**。范围控制与可证明性是同一件事。

验收依据：

- 对已完整覆盖的规则与配置,最优与最差初始期望都符合目标 RTP
- 所有可兑现节点满足选定的继续/停止条件
- 解出的极端策略加入模拟器回归
- 金额舍入、最高赔付、最低概率限制进入验证
- 蒙特卡洛报告给出样本量、方差、**置信区间**与尾部事件覆盖
- 若状态空间无法完整求解,**明确报告覆盖范围与未证明部分**；固定策略模拟的结论限定为"已测试策略符合容差"

## 3. 首版赛制、终局表与操作范围

### 3.1 首版操作范围（v1 大幅缩减）

| 项 | 首版 | 后续阶段 |
|---|---|---|
| 进攻方向 | **左 / 中 / 右（3）** | 增加上下角 |
| 射法 | **推射 / 抽射（2）** | 吊射作为**独立射法**（明确其合法目标区域,不再同时定义为区域再与射法组合） |
| 进攻组合 | **6 种** | 扩展后再评估 |
| 防守 | **方向 3 选 1** | 增加提交前选择的扑救时机 |
| 压力 | 不在首版 | 低/中/高三级离散状态 |
| 阵容 | 不在首版 | 少量特质 + 一次教练调整 |
| 模式 | **仅完整模式** | 快速模式 |

**首版不使用实时反应速度判定金钱结果。** 「提前扑」「等一拍」若加入,是**提交前选择的战术**,不要求玩家在动画中抢时间。

### 3.2 终局与结算表

| 项目 | 规则 |
|---|---|
| 常规赛 | 最多五轮,每轮双方各执行一次罚球 |
| 阶段顺序 | 首版固定玩家先攻,随后防守 |
| 提前胜负 | 每次结果后检查比分与双方剩余次数；胜负已锁定即终局 |
| 收钱窗口 | **非终局的完整攻防轮结束后**；不在动作或视频进行中兑现 |
| 常规取胜 | 使用已纳入现金模型的胜利返还函数,**不追加未经校准的固定加成** |
| 常规落败 | 返还为零；此前所有可兑现报价已把该风险纳入计算 |
| 五轮平局 | 进入限定骤死赛 |
| 骤死规则 | 双方各罚一球为一组；一方进另一方失即结束；双方同结果则继续 |
| 骤死上限 | **首版最多三组**；仍平局按公开配置的平局返还函数结算 |
| 完美大战 | **首版不设现金加成**；改为"射门全中"等非金钱成绩记录 |
| 已终局 | 自动结算一次,关闭继续、收钱与调整入口 |

「最多三组骤死」是产品自定义的限定赛制,**须在规则页明确**。平局返还必须进入模型,不能临时增加一次未公布的随机决胜。

**完整比赛最多 16 个罚球阶段**（五轮常规 10 个 + 三组骤死 6 个）。该上限有利于完整求解；含骤死的时长另行测量。

### 3.3 双倍罚球（首版不做）

当前现金价值 `C`,命中得 `2C`、失败得 0,则 `期望 = p × 2C`,与收钱 `C` 相同要求 `p = 50%`。将来若加入,二选一：

| 方案 | 规则 | 适用条件 |
|---|---|---|
| 独立双倍分支 | 命中率固定 50%,命中 `2C`,失败 0 | 压力、记忆、射法、特质**均不改变**该分支 |
| 可变成功率分支 | 命中率 `p`,命中返还 `C/p`,失败 0 | 使用决策时条件概率；须满足概率与最高赔付限制 |

进入该分支后独立终局,不返回主比赛。概率或报价变化必须在动作提交前重新展示。

## 4. 深度系统（分阶段,首版只做 D1 + D2 + D4 + D6）

### 4.1 D1 对手原型、赛前倾向与场内线索（首版）

**目的：让第一脚就有判断依据,并形成跨局学习。** 解决 v1 "第一轮热力图为空"的缺陷。

三种门将原型：

| 原型 | 可感知行为 | 玩家可学习的内容 |
|---|---|---|
| **预判型** | 关注最近射门方向,容易提前移动 | 如何形成倾向、何时反向、何时继续挑战原方向 |
| **反应型** | 较少提前移动,不同射法有不同应对表现 | 如何结合站位与射法选择当前目标 |
| **固执型** | 初始方向偏好明显,调整较慢 | 如何利用基础偏好,并识别其开始调整的时点 |

原型影响**可解释的条件概率与表现**,相关现金分支共同校准。**避免只有标签变化而行为完全相同。**

防守界面必须区分三类信息：

- **赛前倾向** —— 对手配置中的基础偏好,**第一轮即可展示**
- **本场记录** —— 已执行罚球的方向与结果,**显示样本数量**
- **当前线索** —— 对下一脚概率有明确影响的公开提示

前两轮优先用箭头或简短文字表达偏好；**小样本记录不得显示为确定预测**。线索可以带不确定性,但其生成过程、概率意义与报价必须保持一致。

### 4.2 D2 门将记忆：诱导与反制（首版）

**目的：让多脚射门构成一个计划。** 并解决 v1 "可能收敛为固定轮换套路"的风险。

记忆规则：

1. 根据已执行的射门方向更新；进球、被扑、打偏**均留下记录**
2. **最近射门权重较高,较早记录逐渐衰减**
3. **偏移设上限** —— 重复不会让某一区域永久不可用
4. 不同原型使用不同的学习与衰减速度
5. 当前倾向通过站位、重心或图标表达,**动作提交前同步展示概率与现金分支**

玩法链条：

```text
连续尝试左侧
  → 门将记忆向左偏移,下一轮出现可见线索
  → 改打右侧,或继续挑战左侧
  → 新选择改变后续记忆,对手逐渐调整
```

**反向不保证进球**；继续同侧也有公开的成功率与收益分布。

**必须验证的反面情形**：模拟检查是否长期只剩「固定轮换」一种最优套路。若是,则该机制的深度不成立,需调整衰减与上限参数。重复、轮换、诱导、动态切换四类策略都要接受验证。

### 4.3 D4 关键球与赛点体验（首版）

**目的：让比分成为清楚的当前任务。** 由规则引擎判断并返回：

| 情境 | 示例提示 | 表现重点 |
|---|---|---|
| 提前取胜机会 | "这一球进,就赢下大战" | 进球能结束比赛的事实 |
| 必须守住 | "必须扑出,才能继续" | 防守与比赛存续的关系 |
| 扳平机会 | "罚进可把比分追平" | 当前一球的比分意义 |
| 骤死赛 | "本组双方结果不同,就分出胜负" | 两脚结果的配对关系 |

提示按剩余次数计算,**普通进球不能被误标为必胜**。情境本身**不添加隐藏概率或额外奖金**。关键球可用较少 UI、镜头收近与声音变化；完整信息仍可读取。

### 4.4 D6 战报与非金钱成长（首版）

战报最多展示 2–3 个关键事件,**来自真实事件日志**：

- "两次左侧射门后,门将倾向左侧；第三次改打右侧并进球。"
- "本场实际射门 3/3,提前取胜。"

**避免用单次随机结果断言"技术正确"或"失败由玩家造成"**（v1 的示例犯过这个错）。

成长内容：射门全中、守住赛点、使用多种射法等成绩,以及球衣、称号、对手图鉴。**首版不改变金钱概率与赔付**；若将来加入现金权益,须重新纳入模型。

### 4.5 D3 教练调整（后续阶段,随阵容系统上线）

阵容系统上线后增加**每局一次**调整：

- 在完整攻防轮结束、比赛未终局时使用
- 剩余至少两名未出场球员时,可交换其中两人的顺序
- **不消除**比分、压力或门将记忆
- 已出场球员与已提交的当前动作**不可回滚**
- 界面明确展示剩余次数与调整后顺序

**该动作必须纳入完整决策树。仅验证初始阵容整局期望相同,不能保证局中调整中性。** 保留调整、提前使用、比分触发使用三类策略均需验证。

### 4.6 D5 压力与阵容定位（后续阶段）

压力首轮扩展采用**低/中/高三级离散状态**（有限状态控制求解规模）,说明来源、恢复方式与对动作的影响。压力改变条件概率时,现金分支同步更新。

球员定位按能力说明,**不再给出"领先必用"这类规定性结论**：

- 神射手：推射特化,适合追求较高进球概率的局面
- 重炮：抽射特化,提供不同的概率与现金分布
- 冰血：**仅屏蔽规定的压力影响**,不免疫门将记忆,不保证进球
- 艺术家：独立吊射机制加入后提供射法特化

赛前编排提供默认阵容、一键沿用与清楚的特质提示,**准备时间计入整局时长**。

## 5. 核心循环与界面

### 5.1 循环

```text
确认下注与规则
  → 查看对手简报,使用默认阵容
  → 进攻：看线索 → 选方向与射法 → 提交 → 结果
  → 防守：看倾向与记录 → 选方向 → 提交 → 结果
  → 更新比分、记忆、现金价值与下一球任务
  → 终局结算,或在轮末选择收钱 / 继续
  → 简短战报
```

### 5.2 界面信息

- 常驻：比分、双方剩余罚球次数、**当前可兑现金额**
- 当前阶段展示**一个**主要对手线索
- 动作确认区展示该动作的**条件成功率与现金分支**
- 压力（后续阶段）以少量等级与表现反馈显示,详细解释按需展开

### 5.3 双模式（快速模式后置）

v1 称"共用 PRF 分支所以同 RTP",论证不足 —— 同 RNG 只保证随机数生成方式一致。

**修正后的做法**：

- **先完成完整模式,再增加快速模式**
- 快速模式的自动防守必须作为**明确策略写入配置**：读取哪些公开信息、如何选择方向、是否使用时机选项、默认行为如何处理
- 两模式的收益分布与时长**可以不同**
- "RTP 相同"只在通过完整选择路径、信息与收钱规则的验证后对外描述

## 6. 一局示例（现金价值可降,因果表述已修正）

> 仅说明玩法联动,不提供正式现金报价。含后续阶段的阵容与吊射扩展。

赛前阵容「神射手、神射手、重炮、艺术家、冰血」,对手为预判型门将。

| 时点 | 玩家行动与结果 | 比分 | 现金价值 | 后续意义 |
|---|---|---|---|---|
| R1 | 推射左侧进球；防守扑出 | 1–0 | ↑ | 门将开始记录左侧使用 |
| R2 | 再次推射左侧进球；防守失球 | 2–1 | ↑ 后 ↓ | 门将出现偏左站位,玩家已有可利用线索 |
| R2 后 | 使用一次教练调整,交换第三与第五名 | 2–1 | — | 冰血提前,重炮留到第五轮 |
| R3 | 见偏左线索后推射右侧进球；防守扑出 | 3–1 | ↑ | 诱导后的反向形成结果；对手仍有追平可能 |
| R4 | 艺术家吊射被扑；防守失球 | 3–2 | **↓↓** | 现金价值按模型下降,进入最后一轮关键局面 |
| R4 后 | 查看当前报价,选择收钱或继续 | 3–2 | — | 先前已用调整,第五轮由重炮出场 |
| R5 | 若进球,比分 4–2,提前锁胜 | 4–2 | 终局 | 对手只剩一脚,比赛自动终局 |

**表述要点（v1 在此过度归因）**：

- R2 的重复左侧**改变了门将倾向,提高了后续被扑概率**；R3 的结果仍由随机分支决定
- 教练调整**改变了第三与第五轮的条件概率与现金分布**,本次成功不能单独证明因果
- R4 的失败使**可兑现金额下降** —— 这正是鞅条件要求的,不是惩罚设计

## 7. 实现架构与数据契约

### 7.1 分层（与 v1 一致,未偏移）

```
┌─ 表现层  Pixi + 视频播放器 + GSAP            零游戏逻辑,可整层替换
├─ 游戏外壳  轮次状态机 / 攻防阶段机 / UI 状态 / 资产调度
├─ OutcomeProvider（接口）  ←──────── 服务端接入的唯一切换缝
│    ├─ LocalProvider   S0 起即建立
│    └─ RemoteProvider  服务端阶段新增,沿用同一权威事件与展示契约
└─ shootout-math（纯 TS,零依赖,Node 可运行,全单测 + 可完整求解）
```

**`OutcomeProvider` 在 S0 就建立**,表现层从第一版起读取统一结果。阶段结束、按钮禁用与断线恢复**不依赖视频是否播放完毕**。

### 7.2 数据契约（较 v1 大幅扩充）

| 对象 | 必须明确的内容 |
|---|---|
| **ShootoutConfig** | 配置版本、目标 RTP、赛制、概率模型、现金模型、金额舍入、骤死上限、模式自动策略 |
| **MatchState** | 比分、双方剩余次数、阶段、现金价值、公开线索、记忆、压力、阵容、已用调整次数、终局状态 |
| **DecisionQuote** | 状态版本、合法动作、条件概率、结果现金分支、可兑现金额、**报价标识** |
| **DecisionEvent** | 会话、序号、阶段、动作、阵容调整、对应报价与配置版本 |
| **RoundResolution** | 权威结果、比分与现金变化、新线索、关键球情境、下一阶段、终局类型 |
| **Settlement** | **唯一结算标识**、终局原因、实际返还、金额单位、已结算状态 |

数据职责：

- **相同动作重复提交只产生一次有效结果**（幂等）
- **收钱与继续请求竞争时,只接受一个合法状态转换**
- 阵容调整作为**不可回滚的新事件**,不能重写已执行路径
- 断线恢复使用权威状态与已结算标识,**媒体播放位置单独恢复**
- 配置与规则版本**随会话固定**,避免中途改变报价依据

### 7.3 可证明公平（v1 论证已修正）

`commit/reveal` 须绑定**会话、规则与配置版本、完整动作日志**。

揭示可验证"承诺后的 seed 与重放结果一致"。但**单独的 seed 哈希不证明 seed 生成过程无偏** —— 正式随机流程需单独定义与验证。

赛前阵容顺序仍须纳入决策路径哈希输入,防止看到结果后反悔重排。

## 8. 节奏与视频生产

### 8.1 时长按整局测量（参考预算,非强制超时）

完整模式单轮参考预算：

| 环节 | 预算 |
|---|---|
| 看线索与进攻选择 | 3.0 s |
| 进攻结果表现 | 2.0 s |
| 看倾向与防守选择 | 2.5 s |
| 防守结果表现 | 2.0 s |
| 比分更新与收钱决策 | 2.0 s |
| **合计** | **约 11.5 s** |

这些是**体验目标,不作为未经说明的强制动作超时**。赛前准备、引导、加载、关键球与骤死**分别计时**。

完整模式常规比赛 60–90 秒、快速模式 20–30 秒**保留为待验证目标**。须报告常规比赛与含骤死的 **P50 / P95 / P99**,并记录新手与熟练玩家的差异。

快速模式仍有对手罚球结果与比分更新；通过合并展示、短动作与默认阵容减少时间,再用完整流程实测判断目标是否成立。

### 8.2 先验证片段能否覆盖动作,再冻结片单

v1 直接把「16 条主片」当作结论。**v2 改为预算目标,须先通过覆盖验证。**

先做三类样片（角落进球、方向扑救、吊射或中路结果）并检查：

- 选左/选右后的**实际球路与门将扑向一致**
- 特效球不与视频内已有球重复
- 脚触球、遮挡、入网与球网反馈能衔接
- 镜像不破坏文字、角色特征与场景方向
- 横竖屏切换及视频失败降级**保持同一个权威结果**

片单同时记录支持动作、镜像条件、特效接管点与降级表现。

### 8.3 竖屏规格的修正

**v1 把 720×540 称作"竖屏"不准确。720×540 是 4:3**,它适合作为**竖屏 UI 内的视频窗口**。

若目标是**真正的竖向全屏画面**,需另外明确长宽比、机位与裁切方式（参考平台另有 720×2560 的全高侧栏,即为此类用途）。两种方案的资产与机位要求不同,须在片单冻结前选定。

其余规格沿用参考平台 ffprobe 实测值：H.264、**无音轨**、横屏 1280×720 @24fps、背景循环 8s @218kbps、每条配首帧 poster、`media-manifest.json` 驱动渐进加载、pixi-filters 按需 tree-shake。

## 9. 验证计划

### 9.1 数学与规则

- 验证提前胜负、双方剩余次数、常规平局、骤死同结果与上限结算
- 对完整覆盖的模型求**最优与最差期望**,并定位不一致节点
- 测试固定、轮换、诱导、自适应射法与动态收钱策略
- 阵容上线后覆盖初始排序与教练调整；快速模式上线后覆盖自动防守
- 检查舍入、赔付上限、最低概率及终局奖金的**共同影响**
- 模拟输出 RTP、取胜率、赢钱概率、方差、现金分布、终局路径与**置信区间**

### 9.2 玩法理解与深度（灰盒阶段免费试玩）

| 验证问题 | 观察方法 |
|---|---|
| 玩家是否在读对手 | 提交前简短说明依据,检查是否使用了公开线索 |
| 是否理解记忆 | 能否描述先前选择如何影响下一脚 |
| 是否只剩一种套路 | 分析不同对手下的动作序列,并与自动策略结果对照 |
| 比分是否有意义 | 是否理解当前需要进球、扑救或已锁胜 |
| 教练调整是否有代价 | 能否说明提前使用某名球员后顺序的变化 |
| 战报是否可信 | 能否与实际日志对应,是否夸大随机结果的因果 |
| 信息是否过多 | 记录决策时间、误读、无目的点击与引导需求 |

约 **8–12 名**不同熟练度测试者即可发现主要理解问题。**该轮结果用于改设计,不作为留存或商业收益的统计证明。**

**核心深度的通过标准**：玩家能讲出一段可执行计划,实际玩法给出对应反馈,且存在多种符合不同目标的选择。即使用自动轮换也能完成操作,仍要确认主动观察是否带来可感知的比赛体验。

## 10. 分阶段范围（替代 v1 的 M0–M5）

| 阶段 | 内容 | 出口条件 |
|---|---|---|
| **S0 结算灰盒** | 基础方向与射法、比分、提前终局、限定骤死、收钱与现金价值 | 状态与终局表完整；求解范围明确；**无无损增值区间** |
| **S1 核心深度** | 对手原型、赛前倾向、有限门将记忆、关键球提示、简短战报 | 玩家能读懂并形成计划；新增状态通过数学验证 |
| **S2 构筑联动** | 少量球员特质、压力等级、一次教练调整 | 构筑与调整有可见后果；自适应策略验证通过 |
| **S3 表现验证** | 少量占位片、球轨迹、声音、横竖屏、弱网降级 | 所选方向、球路、扑救与结果一致；节奏实测通过 |
| **S4 快速模式** | 明确自动防守策略,减少展示与操作时间 | 模式目标 RTP 验证通过；新手能理解防守收益与收钱 |
| **S5 资产与扩展** | 正式片单、本地化、成长、杯赛；按需加入双倍分支 | 前面规则与数据稳定；每项扩展单独验收 |

**首版完成 S0 与 S1。** 先证明核心选择有趣,再增加构筑联动。正式资产批量制作安排在 S3 表现覆盖验证之后。

杯赛后续可通过对手学习速度、不同倾向与情境变化增加挑战。连场投注或奖金若加入,须单独定义会话与结算边界。

## 11. 风险

| 风险 | 性质 | 应对 |
|---|---|---|
| **现金模型出现无损继续区间** | **最严重**（v1 已犯） | S0 出口条件即为"无无损增值区间"；完整求解检查每个可兑现节点 |
| 鞅条件与赔付上限/舍入冲突 | 高 | 若无法同时满足,修改规则或明确放宽数学目标,不在界面继续承诺 |
| 门将记忆收敛为单一套路 | 高 | 衰减 + 偏移上限；把"是否只剩固定轮换"列为明确验证项 |
| 状态空间无法完整求解 | 高 | 操作面缩减、压力离散三级、记忆设上限、骤死三组上限；无法完整求解时明确报告覆盖范围 |
| 认知负担过重 | 高 | 首版仅 6 种进攻组合 + 3 防守方向；系统分阶段加入 |
| 固定片段与任意球路不匹配 | 高 | S3 先用样片验证覆盖,再冻结片单 |
| 会话时长失控 | 中 | 整局测量 P50/P95/P99；参考预算非强制超时 |
| 竖屏方案未定 | 中 | 片单冻结前选定"4:3 视频窗口"或"真竖向全屏" |
| 差异化结论未验证 | 中 | 竞品实测完成后再按已验证样本描述差异 |
| 媒体体积拖垮弱网 | 中 | poster 兜底 + 渐进加载 + 竖版码率再压一档 |
