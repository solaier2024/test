# 点球大赛：问题修订建议与玩法深度扩展

> 日期：2026-10-09
>
> 状态：独立建议稿
>
> 适用范围：点球即时赢产品的玩法、结算、交互与实现规划
> 依据：[原玩法方案](gameplay-design.md)

本文整理现有方案需要修订的问题，并提出可分阶段落地的玩法扩展。文中的规则取舍是推荐方案；数学示例用于说明约束，尚未形成经过求解、模拟或认证的正式赔付配置。

## 1. 推荐方向

保留五轮比分、交替攻防、主动收钱和可读对手。围绕“观察对手 → 做出计划 → 对手调整 → 利用或改变计划”建立局内深度。

玩家的目标分为两层：

- **比赛目标**：进球、扳平、守住赛点、赢下大战。不同选择可以改变比赛取胜概率。
- **金钱目标**：选择符合自身偏好的兑现时机与收益分布。若采用策略 EV 中性的产品目标，不同比赛胜率必须通过完整结算模型平衡。

比赛胜率、赢钱概率、期望收益和收益方差需要分别定义。比赛胜率提高，不直接等于金钱期望提高；金钱波动增加，也不直接等于逆转概率提高。

首版优先完成结算闭环和少量可感知的深度系统。压力、阵容调整、双模式和杯赛分别增加，逐项验证其效果与成本。

## 2. 问题与修订优先级

P0 表示正式赔付配置和核心规则冻结前必须解决；P1 表示对应功能上线前必须解决。

| 优先级 | 当前问题 | 推荐修订 |
|---|---|---|
| P0 | 用“命中率 × 倍率步进恒定”推导整局 EV 中性，未纳入失败、比分终局、奖金和收钱 | 以完整状态的现金价值建立模型，求解所有动作与停止策略的期望 |
| P0 | 示例中失败不扣倍率，前两轮继续存在只增不减的区间 | 可兑现金额允许随结果下降；成功增幅与失败损失共同校准 |
| P0 | 常规落败、平局、提前锁胜、完美加成之间的关系不完整 | 建立唯一终局与结算表，明确事件顺序、兑现窗口和加成规则 |
| P0 | 列举策略的蒙特卡洛被称为“全部策略的证明” | 增加完整状态求解、最优与最差策略边界；模拟报告给出置信区间 |
| P1 | “落后必须高波动”的结论混淆比赛分数与金钱方差 | 根据扳平、取胜和兑现目标分别解释选择价值 |
| P1 | “双倍罚球”仍可能受压力和特质影响，却固定命中翻倍 | 固定独立 50% 分支，或按条件命中率重新计算赔付；首版暂缓 |
| P1 | 共用 PRF 被当作双模式同 RTP 的充分条件 | 明确自动防守策略，验证其信息、选择与停止规则 |
| P1 | 第一轮热力图为空，五轮历史数据较少 | 增加赛前倾向与可见线索，区分基础倾向和本场记录 |
| P1 | 门将记忆容易收敛为固定轮换套路 | 增加有限记忆、衰减与可见站位，支持主动诱导和后续反制 |
| P1 | 七区域、力度、时机、阵容同时出现，认知和时长预算偏紧 | 首版缩减选择，分阶段增加系统；实测整局时间 |
| P1 | 固定结果视频与任意球路、门将方向是否匹配尚未验证 | 用少量样片验证轨迹、遮挡和扑救一致性，再冻结片单 |
| P1 | 阵容路径锁定与后续局中调整缺少协议定义 | 把合法调整作为新的权威决策事件，记录状态版本和不可回滚的动作日志 |

## 3. 结算与 EV 中性的修订建议

### 3.1 明确 EV 中性的作用范围

将“不同策略的金钱期望相同”明确为本产品选择的数学目标。它涵盖玩家能够使用的公开信息、阵容、动作、合法调整、模式和收钱策略。

建议统一定义：

- 下注额为 W。
- 目标 RTP 为 r，初始整局期望返还为 W × r。
- C(s) 为状态 s 下当前可兑现的现金价值。
- G(s) 为终局状态的实际返还。
- 概率必须以玩家决策时可见的信息为条件计算。

RTP 使用“实际返还 ÷ 下注额”，返还是否包含本金应在规则中明确。容差使用“百分点”表达，避免把相对误差与绝对误差混用。

若要求玩家在任一可兑现状态选择继续或收钱都保持相同 EV，一个充分条件是：

```text
对每个可到达决策状态 s、每个合法继续动作 a：

C(s) = Σ P(s' | s, a, 可见信息) × C(s')

终局状态：
C(s) = G(s)
```

后继状态的现金价值应包含后续收益、损失、终局和信息变化。只平衡单次进球的概率与奖励不能替代这个条件。

### 3.2 修复前两轮的无损继续区间

原示例中，R1 后可收 1.70x。继续 R2 时，罚失或防守失败不扣倍率；五轮赛制也不会在第二轮就淘汰玩家。只要成功仍能提高倍率，R2 后收钱就优于 R1 后收钱。

**推荐修订：区分比赛比分与可兑现金额，可兑现金额允许因失败下降。**

- 射门失败可以继续比赛，同时降低当前现金价值。
- 对手进球影响比分，也可以降低当前现金价值。
- 进球或扑救成功对现金价值的贡献，与失败分支一起校准。
- 比赛失败归零、平局返还等终局约束，也进入完整求解。
- HUD 显示当前可兑现金额；潜在终局奖励应单独标注。

下面是单步示例，当前现金价值均为 10 个货币单位：

| 示例选择 | 成功概率 | 成功后现金价值 | 失败后现金价值 | 单步期望 |
|---|---|---|---|---|
| A | 80% | 11 | 6 | 0.8 × 11 + 0.2 × 6 = 10 |
| B | 50% | 14 | 6 | 0.5 × 14 + 0.5 × 6 = 10 |

该示例说明可以让成功率、收益分布和波动不同，同时保持单步期望相同。它没有包含比赛终局，不能直接作为正式推射或抽射参数。

正式模型需要验证全部后继状态。若配置无法同时满足现金价值、落败归零、奖励上限和所有动作同 EV，应修改规则或明确放宽数学目标，不能在界面继续承诺已经成立。

### 3.3 用完整求解补足策略验证

在有限状态、有限轮数下，分别求最优和最差金钱策略：

```text
Vmax(s) = max { C(s), Σ P(s' | s,a) × Vmax(s') }
Vmin(s) = min { C(s), Σ P(s' | s,a) × Vmin(s') }

仅在允许收钱的状态加入 C(s) 选项。
终局状态使用 G(s)。
初始下注后尚未允许收钱的状态，按合法动作求值。
```

需要覆盖的状态包括比分、剩余罚球次数、公开线索、记忆、压力、阵容、调整次数、模式和现金价值。用于求解的状态抽象应保留所有会影响概率、赔付和决策的信息。

验收依据：

- 对已完整覆盖的规则与配置，最优和最差初始期望都符合目标 RTP。
- 所有可兑现节点满足选定的继续与停止条件。
- 解出的极端策略加入模拟器回归。
- 金额舍入、最高赔付和最低概率限制进入验证。
- 蒙特卡洛报告包含样本量、方差、置信区间和尾部事件覆盖。

若状态空间无法完整求解，应明确报告覆盖范围和未证明部分。固定策略模拟可作为检查，结论限定为“已测试策略符合容差”。

### 3.4 双倍罚球的正确条件

当前可兑现金额为 C，命中获得 2C，失败获得 0：

```text
期望返还 = p × 2C
与收钱 C 相同，需要 p = 50%
```

后续可以选择两种设计中的一种：

| 方案 | 规则 | 适用条件 |
|---|---|---|
| 独立双倍分支 | 命中率固定 50%，命中 2C，失败 0 | 压力、记忆、射法与球员特质均不改变该分支 |
| 可变成功率分支 | 命中率为 p，命中返还 C/p，失败 0 | 使用决策时条件概率；满足概率与最高赔付限制 |

进入该分支后独立终局，不再返回主比赛。概率或报价需要变化时，必须在动作提交前重新展示。首版不加入这条分支。

### 3.5 双模式的一致性

快速模式的自动防守应作为明确策略写入配置，规定读取哪些公开信息、如何选择方向、是否使用时机选项以及如何处理默认行为。

同 RNG 算法只保证随机数生成方式一致。模式 RTP 一致还需要对完整选择路径、信息与收钱规则进行验证。

推荐先完成完整模式，再增加快速模式。两种模式的收益分布和时长可以不同；“RTP 相同”在通过验证后对外描述。

## 4. 推荐的首版赛制与终局表

以下为可供实现的推荐取舍，赔付函数仍需按第 3 节求解。

| 项目 | 推荐规则 |
|---|---|
| 常规赛 | 最多五轮；每轮双方各执行一次罚球 |
| 阶段顺序 | 首版固定玩家先攻、随后防守 |
| 提前胜负 | 每次结果后检查比分与双方剩余罚球次数；胜负已锁定即终局 |
| 收钱窗口 | 非终局的完整攻防轮结束后；不在某个动作或视频进行中兑现 |
| 常规取胜 | 使用已纳入现金模型的胜利返还函数，不追加未经校准的固定加成 |
| 常规落败 | 返还为零；所有此前可兑现报价已把该风险纳入计算 |
| 五轮平局 | 进入限定骤死赛 |
| 骤死规则 | 双方各罚一球为一组；一方进另一方失则结束；双方同结果则继续 |
| 骤死上限 | 首版建议最多三组；仍平局则按公开配置的平局返还函数结算 |
| 完美大战 | 首版不设置现金加成；以“射门全中”等非金钱成绩记录替代 |
| 已终局 | 自动结算一次，关闭继续、收钱和调整入口 |

“最多三组骤死”属于产品自定义的限定赛制，应在规则页明确。平局返还也必须进入模型，不能临时增加一次未公布的随机决胜。

完整比赛最多执行 16 个罚球阶段：五轮常规的 10 个阶段，加三组骤死的 6 个阶段。上限有利于完整求解；包含骤死的时长另行测量。

提前锁胜与“必须完成 5/5 才算完美”存在冲突。首版记录实际执行的射门全中情况，例如 3/3 提前取胜。后续若恢复完美现金路线，应同时重新定义赛制、重叠奖励和结算。

## 5. 推荐核心循环与操作范围

```text
确认下注与规则
  → 查看对手简报，使用默认阵容
  → 进攻：看线索 → 选方向与射法 → 提交 → 结果
  → 防守：看倾向与记录 → 选方向 → 提交 → 结果
  → 更新比分、记忆、现金价值与下一球任务
  → 终局结算，或在轮末选择收钱 / 继续
  → 简短战报
```

首版进攻采用左、中、右三个方向，加推射、抽射两种射法，共六种组合。防守采用三个方向。后续增加上下角与预先选择的扑救时机。

吊射作为独立射法设计，明确其合法目标区域；避免把它同时定义为区域并再与推射、抽射组合。

界面信息建议：

- 常驻比分、双方剩余罚球次数、当前可兑现金额。
- 当前阶段展示一个主要对手线索。
- 动作确认区展示该动作的条件成功率与现金分支。
- 压力以少量等级和表现反馈显示；详细解释按需展开。

首版不使用实时反应速度判定金钱结果。“提前扑”和“等一拍”若加入，应是提交前选择的战术，不要求玩家在动画中抢时间。

## 6. 玩法与深度扩展

### D1. 对手原型、赛前倾向与场内线索

**目的：让第一脚就有判断依据，并形成跨局学习。**

对手配置包含门将行为模板和射手方向倾向。首版可以从以下三种门将原型开始：

| 原型 | 可感知行为 | 玩家可以学习的内容 |
|---|---|---|
| 预判型 | 关注最近射门方向，容易提前移动 | 如何形成倾向、何时反向、何时继续挑战原方向 |
| 反应型 | 较少提前移动，不同射法有不同应对表现 | 如何结合站位和射法选择当前目标 |
| 固执型 | 初始方向偏好较明显，调整较慢 | 如何利用基础偏好，并识别其开始调整的时点 |

类型影响可解释的条件概率与表现，相关现金分支共同校准。避免只有标签变化而行为完全相同。

防守界面区分：

- **赛前倾向**：对手配置中的基础偏好，第一轮即可展示。
- **本场记录**：已执行罚球的方向与结果，显示样本数量。
- **当前线索**：对下一脚概率具有明确影响的公开提示。

前两轮优先用箭头或简短文字表达偏好；小样本记录不能显示成确定预测。线索可以有不确定性，其生成过程、概率意义和报价应保持一致。

验收：新玩家能说出一项对手特征；线索与实际生成模型一致；自动策略读取线索后的结果进入数学验证。

### D2. 门将记忆形成诱导与反制

**目的：让多脚射门构成一个计划。**

推荐记忆规则：

1. 根据已经执行的射门方向更新；进球、被扑和打偏均可留下记录。
2. 最近射门权重较高，较早记录逐渐衰减。
3. 偏移有上限；重复不会让某一区域永久不可用。
4. 不同门将原型使用不同学习与衰减速度。
5. 当前倾向通过站位、重心或图标表达，动作提交前同步展示概率与现金分支。

一种玩法链条是：

```text
连续尝试左侧
  → 门将记忆向左偏移，下一轮出现可见线索
  → 改打右侧，或继续挑战左侧
  → 新选择改变后续记忆，对手逐渐调整
```

反向不保证进球。继续同侧也有公开的成功率与收益分布。记忆应支持多种计划，并通过模拟检查是否长期只剩固定轮换套路。

验收：玩家能够解释自己的铺垫和下一步计划；历史选择对后续状态有可见影响；重复、轮换、诱导、动态切换策略均接受验证。

### D3. 每局一次教练调整

**目的：让赛前构筑能够回应实际比分，并产生机会成本。**

阵容系统上线后，增加一次调整机会：

- 在完整攻防轮结束、比赛未终局时使用。
- 剩余至少两名未出场球员时，可以交换其中两人的顺序。
- 调整不消除比分、压力或门将记忆。
- 已出场球员及已提交的当前动作不能回滚。
- 每局最多一次，界面明确展示剩余次数和调整后的顺序。

例子：冰血原本位于第五轮。第二轮结束后，玩家可把他提前到第三轮应对当前局面，同时接受第五轮由另一名球员出场的后果。

该动作必须纳入完整决策树。仅验证初始阵容整局期望相同，不能保证局中调整中性。

验收：保留调整、提前使用、比分触发使用三类策略均验证；玩家能解释提前使用的收益与后续代价。

### D4. 关键球与赛点体验

**目的：让比分成为清楚的当前任务。**

由规则引擎判断并返回以下情境：

| 情境 | 示例提示 | 表现重点 |
|---|---|---|
| 提前取胜机会 | “这一球进，就赢下大战” | 进球能结束比赛的事实 |
| 必须守住 | “必须扑出，才能继续” | 防守与比赛存续的关系 |
| 扳平机会 | “罚进可把比分追平” | 当前一球的比分意义 |
| 骤死赛 | “本组双方结果不同，就分出胜负” | 两脚结果的配对关系 |

提示按剩余次数计算，普通进球不能被误标为必胜。情境本身不添加隐藏概率或额外奖金。

关键球可使用较少 UI、镜头收近和声音变化。完整信息仍可读取，提示只强调当前最重要的任务。

验收：构造比分边界逐一检查；玩家能理解为何这一脚关键，以及其结果后比赛是否结束。

### D5. 压力与阵容的定位修订

**目的：让已有系统产生可理解的节奏变化。**

压力首轮扩展采用低、中、高三个有限状态，说明其来源、恢复方式及对动作的影响。保持可恢复的路径依赖，并用有限状态控制求解规模。

压力改变条件概率时，现金分支同步更新。冰血仅屏蔽规定的压力影响，不自动免疫门将记忆或保证进球。

球员定位按能力说明：

- 神射手：推射特化，适合追求较高进球概率的局面。
- 重炮：抽射特化，提供不同的概率与现金分布，不固定标为“领先必用”。
- 冰血：压力影响较小，适合玩家判断的高压时点。
- 艺术家：在独立吊射机制加入后提供射法特化。

初期验证少量特质。赛前编排提供默认阵容、一键沿用和清楚的特质提示，准备时间计入整局时长。

### D6. 战报与非金钱成长

**目的：让玩家能回顾自己的计划，并建立持续目标。**

战报最多展示两到三个关键事件：

- “两次左侧射门后，门将倾向左侧；第三次改打右侧并进球。”
- “你把冰血从第五轮调到第三轮；第三轮进球，随后由重炮执行第五轮。”
- “本场实际射门 3/3，提前取胜。”

战报记录选择、状态变化和结果。避免用单次随机结果断言“技术正确”或“失败由玩家造成”。

成长内容可包括射门全中、守住赛点、使用多种射法等成绩，以及球衣、称号和对手图鉴。首版这些内容不改变金钱概率与赔付；如未来加入现金权益，需重新纳入模型。

验收：战报来自真实事件日志；收钱、常规终局、提前终局和平局都能生成；成绩条件可重放检查。

## 7. 一局玩法叙事示例

以下示例包含后续阵容与吊射扩展，仅说明玩法联动，不提供正式现金报价。

赛前阵容为“神射手、神射手、重炮、艺术家、冰血”，对手为预判型门将。

| 时点 | 玩家行动与结果 | 比分 | 后续意义 |
|---|---|---|---|
| R1 | 推射左侧进球；防守扑出 | 1–0 | 门将开始记录左侧使用 |
| R2 | 再次推射左侧进球；防守失球 | 2–1 | 门将出现偏左站位，玩家已有可利用线索 |
| R2 后 | 使用一次教练调整，交换第三与第五名 | 2–1 | 冰血提前，重炮留到第五轮 |
| R3 | 看见偏左线索后推射右侧进球；防守扑出 | 3–1 | 诱导后的反向形成结果；对手仍有追平可能 |
| R4 | 艺术家吊射被扑；防守失球 | 3–2 | 现金价值按模型更新，进入最后一轮关键局面 |
| R4 后 | 查看当前报价，选择收钱或继续 | 3–2 | 先前已使用调整，第五轮由重炮出场 |
| R5 | 若进球，比分变为 4–2，提前锁胜 | 4–2 | 对手只剩一脚，比赛自动终局 |

该例强调三件事：玩家有意识地建立倾向，局中调整有后续代价，比分决定最后一脚的任务。反向、球员特质和关键球均不保证成功。

## 8. 首版范围与后续顺序

| 阶段 | 内容 | 出口条件 |
|---|---|---|
| S0 结算灰盒 | 基础方向与射法、比分、提前终局、限定骤死、收钱与现金价值 | 状态和终局表完整；求解范围明确；无无损增值区间 |
| S1 核心深度 | 对手原型、赛前倾向、有限门将记忆、关键球提示、简短战报 | 玩家能读懂并形成计划；新增状态通过数学验证 |
| S2 构筑联动 | 少量球员特质、压力等级、一次教练调整 | 构筑和调整有可见后果；自适应策略验证通过 |
| S3 表现验证 | 少量占位片、球轨迹、声音、横竖屏、弱网降级 | 所选方向、球路、扑救与结果一致；节奏实测通过 |
| S4 快速模式 | 明确自动防守策略，减少展示与操作时间 | 模式目标 RTP 验证通过；新手能理解防守收益与收钱 |
| S5 资产与扩展 | 正式片单、本地化、成长、杯赛；按需加入双倍分支 | 前面规则和数据稳定；每项扩展单独验收 |

首版完成 S0 与 S1。先证明核心选择有趣，再增加构筑联动。正式资产批量制作安排在表现覆盖验证之后。

杯赛后续可通过对手学习速度、不同倾向和情境变化增加挑战。连场投注或奖金若加入，应单独定义会话与结算边界。

## 9. 实现与数据契约补充

### 9.1 提前建立 OutcomeProvider

在 S0 建立接口与 LocalProvider；表现层从第一版起读取统一结果。服务端接入阶段新增 RemoteProvider，沿用权威事件与展示契约。

客户端按结果呈现比分、价格、终局和线索。阶段结束、按钮禁用与断线恢复不依赖视频是否播放完毕。

### 9.2 建议的数据内容

| 对象 | 必须明确的内容 |
|---|---|
| ShootoutConfig | 配置版本、目标 RTP、赛制、概率模型、现金模型、金额舍入、骤死上限、模式自动策略 |
| MatchState | 比分、双方剩余次数、阶段、现金价值、公开线索、记忆、压力、阵容、已用调整次数、终局状态 |
| DecisionQuote | 状态版本、合法动作、条件概率、结果现金分支、可兑现金额、报价标识 |
| DecisionEvent | 会话、序号、阶段、动作、阵容调整、对应报价与配置版本 |
| RoundResolution | 权威结果、比分和现金变化、新线索、关键球情境、下一阶段、终局类型 |
| Settlement | 唯一结算标识、终局原因、实际返还、金额单位、已结算状态 |

数据职责建议：

- 相同动作重复提交时，只产生一次有效结果。
- 收钱与继续请求竞争时，只接受一个合法状态转换。
- 阵容调整作为不可回滚的新事件，不能重写已执行路径。
- 断线恢复使用权威状态与已结算标识，媒体播放位置单独恢复。
- 配置与规则版本随会话固定，避免中途改变报价依据。

commit/reveal 需要绑定会话、规则与配置版本以及完整动作日志。揭示可以验证承诺后的 seed 与重放结果是否一致；单独的 seed 哈希不证明 seed 生成过程无偏。正式随机流程需单独定义并验证。

## 10. 节奏与视频生产修订

### 10.1 时长按整局测量

以下为待实测的完整模式单轮参考预算：

| 环节 | 参考预算 |
|---|---|
| 看线索与进攻选择 | 3 秒 |
| 进攻结果表现 | 2 秒 |
| 看倾向与防守选择 | 2.5 秒 |
| 防守结果表现 | 2 秒 |
| 比分更新与收钱决策 | 2 秒 |
| 合计 | 约 11.5 秒 |

这些数字是体验目标，不作为未经说明的强制动作超时。赛前准备、引导、加载、关键球与骤死分别计时。

完整模式常规比赛 60–90 秒、快速模式 20–30 秒保留为待验证目标。报告常规比赛与包含骤死的 P50、P95、P99，并记录新手与熟练玩家的差异。

快速模式仍有对手罚球结果和比分更新。通过合并展示、短动作和默认阵容减少时间，再用完整流程实测判断目标是否成立。

### 10.2 先验证片段能否覆盖动作

先验证三类样片：角落进球、方向扑救、吊射或中路结果。检查：

- 选左、选右后的实际球路与门将扑向一致。
- 特效球不会与视频内已有球重复。
- 脚触球、遮挡、入网和球网反馈能衔接。
- 镜像不会破坏文字、角色特征和场景方向。
- 横竖屏切换及视频失败降级保持同一个权威结果。

720×540 是 4:3，可用作竖屏 UI 内的视频窗口。若目标为真正的竖向全屏画面，需要另外明确长宽比、机位与裁切方式。

把“16 条主片”先作为预算目标，覆盖验证通过后再冻结。片单同时记录支持动作、镜像条件、特效接管点和降级表现。

## 11. 验证计划

### 11.1 数学与规则

- 验证提前胜负、双方剩余次数、常规平局、骤死同结果和上限结算。
- 对完整覆盖的模型求最优与最差期望，并定位不一致节点。
- 测试固定、轮换、诱导、自适应射法与动态收钱策略。
- 阵容上线后覆盖初始排序和教练调整；快速模式上线后覆盖自动防守。
- 检查舍入、赔付上限、最低概率及终局奖金的共同影响。
- 模拟输出 RTP、取胜率、赢钱概率、方差、现金分布、终局路径与置信区间。

### 11.2 玩法理解与深度

灰盒阶段先进行一轮免费试玩，观察：

| 验证问题 | 观察方法 |
|---|---|
| 玩家是否在读对手 | 提交前简短说明依据，检查是否使用了公开线索 |
| 玩家是否理解记忆 | 能否描述先前选择如何影响下一脚 |
| 是否只剩一种套路 | 分析不同对手下的动作序列，并与自动策略结果对照 |
| 比分是否有意义 | 玩家是否理解当前需要进球、扑救或已经锁胜 |
| 教练调整是否有代价 | 能否说明提前使用某名球员后，后续顺序发生的变化 |
| 战报是否可信 | 能否与实际日志对应，是否夸大了随机结果的因果 |
| 信息是否过多 | 记录决策时间、误读、无目的点击与引导需求 |

可以先用约 8–12 名不同熟练度的测试者发现主要理解问题；该轮结果用于改设计，不作为留存或商业收益的统计证明。

核心深度的通过标准是：玩家能讲出一段可执行计划，实际玩法给出对应反馈，并且存在多种符合不同目标的选择。用自动轮换也能完成操作时，仍要确认主动观察是否带来了可感知的比赛体验。

## 12. 原方案建议修改的表述

| 原表述 | 建议表述 |
|---|---|
| “命中率 × 倍率步进恒等，所以 EV 中性” | “完整条件状态下的继续、收钱和终局现金价值经求解保持选定的 EV 约束” |
| “落后必须选高波动” | “需要扳平时关注进球概率；追求更高现金回报时比较完整收益分布” |
| “重复区域失败是玩家自己造成的” | “重复改变门将倾向，提高了被扑概率；本次结果仍由随机分支决定” |
| “第五轮成功来自排序决策” | “排序改变第五轮的条件概率与现金分布，本次成功不能单独证明因果” |
