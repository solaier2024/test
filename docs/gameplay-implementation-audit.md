# 点球大赛：玩法实际实现核对

日期：2026-10-09。依据：用户提供的 v2 玩法设计、独立玩法评审稿，以及本地 `src` 中的实际实现。文档中的规划条目不算实现证据。

## 结论

**没有实现整套玩法方案。** 当前是基础点球比赛和部分核心深度系统，前端技术重构已经加入，但赛前构筑、局中调整与跨局目标仍然缺失。

用户感觉玩法单一，原因是每次决策仍主要在左/中/右和推射/抽射之间进行；防守只有方向选择。门将记忆改变概率，但缺少球员轮换、压力变化和教练资源，使观察对手很难与更长的计划结合。写实美术和 Seedance 短片可以改善表现，玩法深度还需要独立实现。

## 逐项核对

| 设计内容 | 实际状态 | 代码与具体差距 |
| --- | --- | --- |
| 左/中/右 × 推射/抽射 | 已实现 | `src/math/actions.js` 生成六个进攻动作，HUD 提供方向与射法选择 |
| 防守三方向 | 已实现 | `defenseOptions()`；目前没有扑救时机选择 |
| 五轮、交替攻防、提前胜负 | 已实现 | `src/math/rules.js`、`engine.js`；结果推进比分与剩余次数 |
| 限定骤死、上限平局结算 | 已实现 | 规则与引擎处理，玩法说明公开最大三组骤死 |
| 轮末收钱、成功/失败返还 | 已实现 | `engine.js` 按报价推进现金，`MatchController` 控制交互与重复提交 |
| 三种门将原型 | 部分实现 | `keeper.js` 有不同学习速度、衰减和偏移上限，实际影响报价；`scene.js` 未按原型区分准备姿态与扑救节奏 |
| 赛前倾向与当前线索 | 部分实现 | 进攻倾向和线索接入报价、侧栏和情报弹窗；手机主操作区没有持续展示门将线索，关键球提示也可能取代该线索 |
| 本场记录 | 部分实现 | 保留玩家射门方向、门将记忆样本与终局事件；尚未形成清楚的对手射手方向/结果记录。当前契约也没有权威的对手实际射向，不能拿玩家扑救方向冒充射手方向 |
| 门将有限记忆、诱导与反制 | 已实现数值机制，体验不足 | 最近射门权重更高、影响设上限；门将实时准备站位没有同步反映当前分布，倾向主要通过文字和概率表达 |
| 关键球与赛点 | 部分实现 | `keyBall()` 和 HUD 有对应提示；“罚进可把比分追平”对任意落后都返回，落后超过一球时表述不准确，需要修正边界 |
| 简短战报、关键事件归纳 | 部分实现 | `app.js` 战报显示全部事件、比分、返还及 seed 校验；没有设计中的 2–3 个关键事件总结和记忆变化复盘 |
| 球员特质：神射手/重炮/冰血 | 未实现 | 没有球员对象、特质参数或相应概率计算 |
| 赛前五人阵容与排序 | 未实现 | `start()` 只接收模拟投入；没有阵容编辑、默认阵容或顺序进入决策路径 |
| 低/中/高压力 | 未实现 | 比分情境不等于压力系统；没有压力状态、来源、恢复或动作影响 |
| 每局一次教练调整 | 未实现 | 没有轮末交换未出场球员、调整次数、事件或合法性检查 |
| 独立吊射 | 未实现 | 射法配置仅有 `placed`、`driven`；没有吊射合法区域、概率与表现 |
| 快速模式/自动防守 | 未实现 | 没有模式选择、自动策略配置或对应完整流程 |
| 非金钱成绩、称号、球衣、对手图鉴 | 未实现 | 没有成绩判定、解锁或持久化；逐球流水不构成成长系统 |
| 杯赛进程 | 未实现 | 每次开局独立，没有阶段目标、对手序列或晋级进程 |
| 扑救时机、上下角、双倍分支 | 未实现，设计中也为扩展项 | 需要分别定义规则、合法组合和验证范围，不能仅增加按钮 |

## 已完成与尚未验收的区别

原规则与呈现已有自动测试和浏览器检查记录，详见 `browser-qa.md`。这些检查覆盖现有实现，不覆盖尚未加入的阵容、压力、调整等系统。

v2 将 S2 构筑、S4 快速模式和 S5 成长/杯赛列为后续阶段。阶段规划解释了当前范围，但并不意味着这些玩法已经完成。S1 中的原型动作、记录、关键球与战报也仍有上表所列缺口，不能笼统宣称 S1 全部验收。

重复、轮换等策略的期望返还检查，也不能代替“是否只有一种最优比赛套路”的玩法验证。设计中的 8–12 人理解度试玩尚没有完成记录。

## 增加深度的实施顺序

1. **补齐已有机制的反馈。** 让门将准备站位对应公开倾向，手机直接看到当前线索，区分双方记录，修正关键球边界，战报归纳真实事件。让玩家能看出自己的选择怎样影响下一轮。
2. **加入五人阵容与特质。** 提供默认阵容和排序；神射手特化推射、重炮特化抽射、冰血只屏蔽规定的压力影响。不同轮次由不同球员出场，形成赛前计划。
3. **加入三级压力与一次教练调整。** 让比分和剩余次数影响压力；轮末只能交换未出场球员，保留比分、记忆和压力，显示剩余调整次数。
4. **加入独立吊射。** 定义合法区域及对手行为适配，避免把吊射当成名称变化的第三个按钮。
5. **加入跨局目标。** 先做不影响概率和返还的成绩/图鉴，再做有明确晋级条件与独立每场结算的杯赛。快速模式随后明确自动防守策略。

增加球员、压力、吊射或自动策略后，报价、结算、事件日志和验证工具需要同步更新；现有验证结果不能直接沿用为新玩法已通过的证明。

## 完成标准

以实际可操作流程验收：能够安排阵容、观察倾向、按比分决定何时使用调整、看到新报价、完成比赛，并在战报中还原真实路径。每项必须有真实状态变化和清楚的规则反馈。

这份核对文档记录的是当前状态与缺口，后续实现仍需逐项更新。
