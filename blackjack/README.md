# DEALER'S CHOICE · LA CASA MANDA

一张 1884 年美墨边境赌馆的二十一点桌。对面坐着一位发牌的女庄家,
牌是规规矩矩发的——**要赌的是坐在这张桌子前的那一小时**。

**纯娱乐模拟,不涉及任何真实货币、不设投注、不发奖金。**
标题页与选桌页都明示了这一点。

角色造型:紧束的酒红缎面束腰(**左肩带滑落**)、深 V 黑蕾丝、黑蕾丝长手套、
宽天鹅绒 choker 配石榴石吊坠、发间珠梳与红丝花,暖金烛光下的边境赌馆荷官。
姿态是**前倾压在小臂上**、肩向前、头偏一侧;**垂眸是常态,抬眼直视留给她热络的时候**
——所以"被她看一眼"是一个会发生在你身上的事件,不是她的默认表情。
**桌上与片头用的是同一批成片**(同机位、同造型),所以不会出现"片头一套、桌上一套"。

实现的是本仓库 [`BLACKJACK.md`](../BLACKJACK.md) 与
[`OPENING_AND_SCORE.md`](../OPENING_AND_SCORE.md) 两份方案;
系列定位见 [`SERIES.md`](../SERIES.md),视频基座路线见 [`VIDEO.md`](../VIDEO.md)。

## 玩法

规则就是二十一点,没有加料:要牌、停牌、加倍、分牌,她按房规补牌,
黑杰克照赔。**这里从来没有出千,也没有"叫破"她这回事**——
曾经有过,后来整套拆掉了,因为那让人一整局都在盯她的手,
而这张桌子想让人看的是她的人和这间屋子。

> **玩法是干净的二十一点;沉浸感是这一款真正做的东西。**

三层叠起来:

### 1. 算牌(基础层)

Hi-Lo。**读数不是 HUD 上的数字,是牌靴里剩下的厚度**——
真实的算牌人就是看这个。左侧那条竖读数就是牌靴,金边越亮表示这副牌越偏向你。

### 2. 她这个人(核心层)

她的神色跟着**这一局真正的结果**走:赢了一手她凉一点,输了一手她热络一点,
黑杰克她会认,而不是照着一张情绪表随机抽。`reactionTo()` 只看结算,
所以她的反应永远是对这一局的反应。

**凑近看(按住 LEAN IN / 按住 L)**留下来了,但它不再是一件"有用"的事:
按住它画面的暗角收紧、混音往前压一点,除此之外什么都不给你。
一个没有收益的动作还留着,是因为**人本来就会这么做**——
这是全作唯一一个纯粹为了沉浸感存在的输入。

### 3. 压上去的分量

旧版驱动暗角和配乐强度的是"热度"(她盯你盯得多紧),那套东西跟着出千一起拆了。
现在驱动它们的是 `pressure()`:**这一局压在台面上的注,占你带来的全部筹码多少**。
五百筹码押十个是个玩笑,剩三十还押十个就是一整晚。
同一个旋钮,换了一个诚实的信号。

### 4. 房规(第三层)

`LA CASA MANDA` 那张桌子上,**她可以随时改一条规则,但要先付钱进底池**
(这一局不许加倍 / 这一局黑杰克平赔 / 这一局不许分牌)。
价钱明写在台面上。于是她不是一台执行规则的机器。

### 三张桌子

| | 牌副数 | 软 17 | 黑杰克 | 她能改规则 | 底注 |
| --- | --- | --- | --- | --- | --- |
| **ONE DECK** | 1 | 停 | 3:2 | 否 | 10 |
| **LA CASA MANDA** | 6 | 补 | 3:2 | **能,每次付钱** | 15 |
| **SIX TO FIVE** | 6 | 补 | **6:5** | 否 | 10 |

**牌副数越少,算牌越有用**;`LA CASA MANDA` 用改规则的权力换掉这份优势,
`SIX TO FIVE` 直接在赔率上收走。所以这三档不只是难度,是三种不同的博弈重心。
规则全部收敛在 `src/game/types.ts` 的 `RULES` 一张表上,
加一张桌子是改配置不是改逻辑。

### 键盘

`H` 要牌 · `S` 停牌 · `D` 加倍 · `P` 分牌 · **按住 `L`** 凑近看 · `空格` 继续

长按对一部分玩家不可行,所以 LEAN IN **点一下也能切换**,两种输入完全等价。

## 画面:她是视频,牌是合成上去的

二十一点有 52 张牌、任意手数、要牌/加倍/分牌。**不可能为每种牌面拍视频。**
所以这一桌的架构是:

```
实时特效层   颗粒、暗角、烟、油灯闪                ← 响应引擎状态,逐帧
牌 / 筹码 / UI(DOM + SVG)                    ← 贴在台布平面上
视频层       她的动作片段                        ← 播完即撤,失败即隐身
兜底成片层   每段视频的首尾帧本身                ← 首屏方案 + 弱网方案
```

### 为什么这张桌子做得起

**她的动作词汇和牌面是正交的。** 不管牌是什么,她只会做这些事——
于是一整局二十一点只要 **6 段短片**加一段开场:

| 片段 | 帧数 | 何时播 |
| --- | --- | --- |
| `idle` | 209 | 桌面空闲时循环:两口呼吸、两次眨眼、垂眸,无缝接回 |
| `deal` | 90 | 发牌。她的目光跟着那张牌出去 |
| `warm` | 90 | 她抬眼看你的那一下 |
| `sharp` | 90 | 她收住了 |
| `shuffle` | 90 | 切牌卡出现。她讨一个换靴的空档。**同时是配乐换乐段的接缝** |
| `natural` | 90 | 黑杰克。她认这一手 |
| `intro` | 366 | 开场 CG,六个镜头 |

**每段片子的首尾帧本身就是一张成片**,所以静止姿态是一个星形图的中心:
N 段而不是 N² 段,任何两个动作之间都通过底下那张成片接上,不会跳帧。

### 不需要 alpha 合成

一旦她的手要盖在牌上,就需要带透明通道的视频,而 alpha 视频在 Web 上很麻烦。
**这个需求是被设计掉的,不是用技术硬扛的:**

| 状态 | 怎么做 | 需要 alpha? |
| --- | --- | --- |
| 静止 | 她是不带 alpha 的循环视频,牌是 DOM,两者在画面上不重叠 | 不需要 |
| 发牌的 0.77 秒 | **全幅视频占满画面**,牌在她手里看不清身份;动作末帧牌落定,这时 DOM 牌元素出现 | 不需要 |

**"用运动把身份问题藏进去"**,于是 95% 的画面完全不需要合成,
而看到的是一双真手把牌发到桌上。

### 牌是画出来的,不是拍的

52 张牌面是程序化 SVG(`src/cards/Card.tsx`)。**这是三件事同时的答案**:
向量在任何尺寸都锐利、不需要和底下的成片连戏、
而且牌面是**原创**的——那个年代的牌背设计并不都在公有领域。

### 机位是钉死的

**这是被玩家指出来才修对的一条,所以写在最前面。**

她曾经是一张照片,所以包住所有图层的那个 `<div>` 上挂了一条 5.6 秒的 CSS 关键帧:
6px 平移加 1.008→1.016 的缩放,当时的注释说这是为了"让静帧读起来像一个端着的机位
而不是一张照片"。换成生成视频之后这条动画留在了原地,
于是**吧台、酒瓶、油灯、台布和她一起,每 5.6 秒来回晃一次**。
在合成后的页面上量出来是**整个房间摆动 11px**,而且不同位置摆的幅度不一样——
那是缩放,不只是平移。反馈原话:"镜头晃动太厉害了,那个场景一直在动。"

片段文件本身从来没问题:每一段的每一个背景块都能**以 0px 对回自己的第 0 帧**。
所以修的是那条 CSS,不是素材。现在那个 `<div>` 叫 `.camera`,**永远不带 transform**。

三道闸门跟着改:

- **`verify-still.mjs`(新增)**——缺的就是这一道。文件级的检查永远抓不到一条 CSS 动画,
  所以它在**合成后的真实页面**上截 9 张、跨 8 秒(比那条动画的周期长,
  两次采样不可能落在同一相位),对每个背景块搜索**能把它对回第一张的整数位移**。
  改之前六个块全挂,最大 11px;改之后六个块全是 0px。
- **`verify-motion.mjs`**——它原来要求酒架和她的脸动得一样多,
  理由是"整幅画面都该是活的"。而满足这条的只有那个缺陷本身。现在酒架换了阵营,
  变成第二个静态基准,断言就是需求本身一句话:**她动,房间不动。**
- **`verify-generated.mjs`**——同一套对齐搜索加到片段文件上,
  这样将来一段真的走了机位的片子是**结构性地**被拒,而不是靠一个均值。
  它和原来那条"原地比像素"的房间预算不重复:把 `idle.mp4` 按 2px 做一圈平移再编码,
  六个房间块里有三个仍在预算内(台布 4.30,限 6,因为一片绿呢往旁边挪一像素看着差不多),
  而五个对齐块全部报出了位移。

**油灯还在闪、烟还在飘、颗粒和浮尘还在动**——那些都不是机位。

### 生成片段与光流流水线

**她的六段片子现在是生成的**(Wan 2.7 `image2video`,首尾帧都喂主成片,
所以造型锁着、循环自己就闭合;细节见 [`clipsrc/openart/README.md`](clipsrc/openart/README.md))。
**下面这条光流流水线仍然在用,但只用于开场 CG**——开场是从静帧插出来的,
六个镜头的推轨(`pushIn()` 的 `zoompan`)是**故意的电影语言**,和上面那条桌面机位是两回事。

所有开场关键帧都是**同机位**渲染的,两张只差一个动作的图正是稠密光流要的输入:

```
关键帧对 → ffmpeg minterpolate 稠密光流 → 按缓动曲线重采样 → VP9 / H.264 双尺寸 + poster
```

```bash
node scripts/build-clips.mjs          # 全部
node scripts/build-clips.mjs deal     # 只重建某几段
node scripts/build-clips.mjs intro    # 只重建片头
FORCE=1 node scripts/build-clips.mjs  # 忽略缓存
```

需要 `ffmpeg` 与 `ffprobe`。产物已提交,只有改了关键帧才要重跑。
稠密形变缓存在 `node_modules/.clipcache/`,**所以只调时序的重建是秒级的**——
光流每对关键帧只算一次 48 步,之后所有时序都是在那条曲线上按缓动重采样。

三个坑,代码里都留了注释守着:

- **`minterpolate` 会丢掉首尾两个区间。** 直接喂两张图出来 0 帧。
  输入必须垫成 `[a, b, b]`,才恰好剩一个区间、输出 `steps+1` 帧。
- **image2 解复用器认扩展名不认字节。** 一张 JPEG 改名成 `.png` 会被静默丢弃,
  片子悄悄变短还不报错。所以每帧先过 `normalised()`,并在编码后断言帧数一致。
- **光流很贵,改时序不该重跑它。** 见上面的缓存。

### 服装锁是反过来做的:底是主成片,各帧只"放行"自己该出的部分

第一版的锁是**把主成片的服装矩形贴到各帧上**。服装确实不动了,
代价却更难看:**各帧之间整幅画面都在差**(吧台 4.2–9.3、左侧酒架 5.3–16.1、
台面 3.2–9.1 mean channel diff),于是光流把整张画面都在形变,
而那块贴上去的矩形**一动不动**——一座冻住的岛浮在漂移的水面上。
更糟的是**她左臂的轮廓在各帧间移动到 51px**(y=420:cool 在 x311,warm/sharp 在 x362,
caught 在 x366),而矩形的左边缘钉在 x=336,**正好落在这条摆动带里面**,
所以缝就压在肩头和滑落的肩带上。

现在反过来:

- **底 = 主成片的整幅画面**,各帧只通过一个 **gate** 贡献自己该贡献的部分
  (表情帧 91% 的画面被钉住,发牌 / 洗牌帧 69%)。同一个房间,不再有漂移的水面。
- **gate 是个穹顶,不是方框。** `arch` 把两侧的**下缘抬起来**,
  所以它在中间够到她的下巴与颈带,却**永远够不到肩膀和那条肩带**。
  羽化加宽到 26–30px,边界落在平坦的皮肤和背景上而不是蕾丝上。
- **呼吸不再是一张生成的关键帧,而是主成片自身的位移场**(`BREATH`):
  径向椭圆衰减 + 双线性采样,`sy = y + lift·w`(起伏)、`sx = x - spread·w·u`(扩张)。
  待机片因此**完全不过光流**——每一帧都是主成片被推了一下,
  `idle.webm` 也从 1248KB 降到 700KB。

`verify-seam.mjs` 守着这四条:gate 之外与主成片的差(均值 0.82–0.85、最差单像素 9)、
**她的手臂相对主成片只偏 0.9px**(限 2px)、羽化带里的细节**不高于**主成片在那里的细节
(所以没有硬边)、以及**待机片每一帧都仍然是主成片的某个 warp**
(在 25 个幅度里拟合,最差残差 0.99,限 7)。最后一条比"位移预算"强:
它不是说服装没动太多,而是说**服装只可能这样动**。

### 视频层:待机片是常亮的底床,动作片叠上去淡入

旧的视频层是**一个 `<video>` 换 `src`**,于是每次换片都要重新拉流、重新解码,
中间那一下就是可见的闪;`onStalled` 还会**直接把整个人物层藏掉**。
加上情绪片停在 warm/sharp/caught 而待机片从 cool 起头,**每一手结束都有一次姿态跳变**。

现在:**每段片子一个 `<video>` 元素**。待机片在 z-index 1 上**不间断地播**,
是一张不透明的底床;动作片在 z-index 2 上淡入淡出(150ms),
所以**总覆盖率永远不掉到 0**,`onStalled` 这个处理器也就整个删掉了。
露出的时机挂在 `requestVideoFrameCallback` 上——
那是**唯一**能说明"一帧真的已经上屏"的信号(`readyState` / `canplay` / `play()`
三个都可以为真而合成器手里还是 poster)。片段词表里**每一段都改成了往返**:
从 cool 出发、回到 cool,所以"星形拓扑"这个说法才第一次成立,`cool` 片也就删掉了。

特效层同时减负:DPR 从 2 降到 1、颗粒预先拼成一张超尺寸的 sheet 单次 `drawImage` 偏移绘制、
暗角按量化后的 `(heat, lean, w, h)` 烤到离屏 canvas 上缓存、30fps 上限;
分量模型仍然每 250ms 更新,但只在 `Math.round(heat·200)` 变了才重绘。
**10 秒牌桌的主线程耗时从 3145ms 降到 1296ms**(1600×900,占单核 31.5% → 13.0%),
`verify-smoothness.mjs` 量出的解码丢帧率从 **7.32%(不及格)降到 2.14%**,
画面空白的最长一段从 67ms 降到 17ms。

## 开场 CG

12.87 秒六个镜头,全程暖金烛光(**不是**冷蓝的纪录片调,也不是左轮对决那种肃杀):

1. 雨后的巷子,坎蒂纳门口泼出来的暖光铺在湿石板上——这是一句邀请,不是一座荒镇
2. 穿过赌馆:法罗的台布、骰笼、吧台边笑着的人,房间是活的
3. 她低头看牌 → **抬眼看你**。落点用的是 warm 而不是静息那张:
   静息那张是低头看向别处的,所以"迎上镜头"是一件发生在你身上的事,不是她的默认状态
4. **微距:她戴蕾丝手套的手在切牌。** 虚焦背景里是她的红缎胸衣
   和天鹅绒 choker,所以这双手是谁的没有疑问
5. 一张牌、一杯酒、一把空着的椅子——全片唯一直接对玩家说话的一镜
6. 她的一个笑,片名压上

镜间 0.4 秒 `xfade` 叠化,首尾各一次淡入淡出。

**它不教任何东西。** 这一版是正常的二十一点,没有出千、没有要盯的手法,
所以片头不承担教程,只负责把这个房间卖给你:一盏灯、一副牌、一把空椅子。
台词也是这样写的——最后两句落在椅子和她的脸上,片头要的只是**你坐下**。

字幕**按片长的比例定位**而不是按秒数(`Intro.tsx` 的 `CUES`),
所以重剪片头不会把台词甩到错误的镜头上。中途切语言立刻换轨。

只播一次(`localStorage`),标题页留了一个 **WATCH THE OPENING / VER LA APERTURA**
随时重看。点画面任意处、空格 / 回车 / Esc、或右下角 SKIP 都能跳过,**第一帧就能跳**。
开了"减少动态效果"偏好的人直接跳过,不播。

## 配乐:一支坎蒂纳里的北墨乐队

**全部 WebAudio 运行时合成,一个音频文件都没有**,也没有用任何外部音包——
所以没有需要署名的第三方素材,也不存在授权风险。

第一版是钉在一个和弦上的哈巴涅拉。纸面上讲得通,做出来像酒店大堂。
**边境午夜的坎蒂纳不是氛围铺底,是角落里一支吵到你得凑近说话的乐队。**
所以现在是 **norteño**:

| | |
| --- | --- |
| 速度 | **116 bpm** 的 polka 感(旧版 72,这是它听起来客气的最大原因) |
| 骨架 | Bajo sexto 的 **oom-pah**:正拍根音、二拍五音,永不停 |
| 反拍 | **手风琴和弦戳** + **吉他 rasgueado 扫弦**同时打在反拍上 |
| 和声 | `i – i – iv – V7`(D),**真的在走**,不再是一个不动的低音 |
| 节奏乐器 | Palmas、claves、tambora,**往前提**而不是闷在混响里 |
| 混响 | 节奏组的 room send 从 0.34 降到 **0.11** |
| 旋律 | 手风琴主奏,牌靴对你有利时**下方叠一个三度**——这套风格的招牌平行三度 |
| 彩头 | 赢钱时来一声 **grito**(角落里有人吼那一下) |

### 三度仍然绑她"表现出来"的情绪

这条原则没动,只是**升级了**:以前是一个音在 F(174.61 Hz)和 F♯(185.00 Hz)
之间翻;现在是**整个主和弦在 D 小调和 D 大调之间翻**。
绑的仍然是 `readDealer()` 返回的 `shown`,**永远不绑 `truth`**——
所以配乐依然是她表演的一部分,和她的脸一样可靠,也就是一样不可靠。
有测试断言换 `truth` 不动配乐。

### 洗牌仍然是乐句的接缝

她每次洗牌播一段**真的离开主调**的过门(V of V 进属和弦,北墨乐队示意下一段的写法),
回来时换乐句。所以听觉上的循环远长于写出来的四小节,**而每次重置都有画面上的理由**。

### 可听可测

`scripts/render-score.mjs` 把**真实音频图**(`MediaStreamDestination` 挂在 master 上,
不是为测试另写一份编排)录成 wav,所以配乐是能打开来听的:

```
title          onsets/s   4.4   centroid  1420 Hz   rms  -32.7 dBFS   peak -13.0 dBFS
table_cold     onsets/s   6.0   centroid  1885 Hz   rms  -30.2 dBFS   peak -12.7 dBFS
table_hot      onsets/s   6.2   centroid  1981 Hz   rms  -28.2 dBFS   peak -11.8 dBFS
shuffle_seam   onsets/s   6.0   centroid  1960 Hz   rms  -27.4 dBFS   peak  -8.8 dBFS
opening        onsets/s   7.3   centroid  1970 Hz   rms  -26.5 dBFS   peak  -9.8 dBFS
```

`scripts/verify-audio.mjs` 把这三个量变成断言:**每秒 ≥5 个节奏事件**(热烈)、
**频谱质心 ≥1700 Hz**(手风琴和掌击在前面而不是在混响后面)、
**电平 ≥−32 dBFS 且不削顶**,外加一条"满编排必须比薄编排更响",
否则那三个情绪旋钮就没在干活。"听起来更热烈"不可测,但**让它听起来更热烈的那些东西都是数字**。

### 混音:黑杰克落下来的时候隔壁的钢琴停了

| 事件 | 压多少 | 保持 | 释放 |
| --- | --- | --- | --- |
| 翻牌 | −8% | 0.12s | 0.5s |
| 推筹码 | −6% | 0.10s | 0.4s |

**而黑杰克落定那一下,隔壁的钢琴直接停,四秒内不回来。**
这是这个类型最老的一个手势,而它几乎不要钱——钢琴本来就是单独一条总线。
这个手势原来挂在"叫破"上,那套东西拆掉之后它换了一个更该有的位置:
一整晚只会发生几次、而且发生的时候整张桌子都该安静一下的那件事。

## 她的声音:发牌与报点

两层,单独任何一层都不够。

### 1. 哼音(coo),自己合成的

三个失谐锯齿过两组元音共振峰(760 / 1320 Hz),音高**先微降再往上挑 240 音分**,
外加一层带通气声和一段迟到的浅颤音。**往上挑那一下就是"嗲"的来源**——
平的听起来是无聊,往下掉听起来是失望。

它是 WebAudio,所以和别的东西一样过房间混响、一样被 ducking 压、一样被静音掐掉,
**而且永远可用**。

### 2. 台词,走平台语音合成

免费、无需署名、没有音频文件。关键是这一对参数:

```
pitch 1.75    rate 0.9    volume 0.72
```

**高音高配慢语速,才是又软又撩;同样的词用默认参数念出来是火车报站。**
音量 0.72 是故意压在乐队之下——她是在音乐里说话,不是在播报。

哼音先响,台词晚 180ms 跟上,所以句子开始之前那个气口已经在了。

### 覆盖的节点

| 时机 | 例(en / es-MX) |
| --- | --- |
| 入座 | *Sit down, darling. Place your bet.* / *Siéntate, mi vida. Pon tu apuesta.* |
| **发牌** | *Cards, sugar.* / *Cartas, mi vida.*(四句轮换) |
| 要牌 | 只有哼音,不说话——这一下触发最频繁,说话会腻 |
| **报点(你)** | *nineteen* / *diecinueve* |
| **报点(庄家揭牌)** | *house has twenty* / *la casa, veinte* |
| 洗牌 | *A fresh deck, just for you.* / *Baraja nueva, sólo para ti.* |
| Blackjack / Bust / 赢 / 输 / 平 | 各有专句 |
| 抓到她 | *Mm. How did you see that?* / *¿Cómo lo viste?* |
| 叫错 | *Nothing there, sweetheart.* / *Ahí no había nada, corazón.* |

中英西里主轨跟随现有的双语开关(`en` / `es-MX`),说的是哪一种就挑哪一种系统语音,
优先墨西哥/美西女声。节流是 650–900ms,所以句子不会叠在一起。

**静音开关一并静音。** 语音合成不在 WebAudio 里,所以 ducking 管不到它,
只能设音量并在静音时显式 `cancel()`——两件都做了。

### 怎么验

**平台语音在无头浏览器里通常是没有的**,所以 `verify-audio.mjs` 不去录声音,
而是在页面里挂住 `speechSynthesis.speak`,断言**游戏在该说话的时候要了正确的词**。
实测一手牌:

```
"Sit down, darling. Place your bet."  pitch 1.75  rate 0.9  volume 0.72  en-US
"Cards, sugar."                      pitch 1.75  rate 0.9  volume 0.72  en-US
"four"                               pitch 1.75  rate 0.9  volume 0.72  en-US
"house has twenty"                   pitch 1.75  rate 0.9  volume 0.72  en-US
"Mine, I'm afraid."                  pitch 1.75  rate 0.9  volume 0.72  en-US
```

断言里也包含参数本身:pitch < 1.4 就不是她,rate > 1 太赶,volume > 0.85 会坐在音乐上面。

**注意 `render-score.mjs` 录出来的 wav 里没有台词**——语音合成是平台服务,
不经过 WebAudio,录不到;wav 里有的是它底下那层哼音。

## 移动端

竖屏不是把桌面版缩小,是另一套排法:`object-fit: cover` 把 16:9 的成片塞进
390×844 只能看见约四分之一的画面宽度。所以竖屏把屏幕切成**明确的分带**:

```
0    – 44dvh   舞台(她)
26   – 44dvh   牌(压在舞台下半部,也就是桌面上)
45   – 50dvh   读数条(牌靴横放)
50   – 54dvh   提示行
54   – 100dvh  操作区
```

用 `dvh` 而不是 `vh`,地址栏收起时不会把底部按钮顶出屏幕。其它几件事:

- **`hover` 全部关进 `@media (hover: hover)`。** 触屏上 hover 会"粘住",
  另外补了一组 `:active` 反馈
- **安全区**:`viewport-fit=cover` + `env(safe-area-inset-*)`,画面铺到刘海底下,控件不进去
- **所有按钮 ≥50px 高**(离桌那个链接 44px)
- **手机档片源**:`(max-width: 860px)` 时自动取 `.sm` 版本,
  **网速细的时候也取**(见下一节),并且只加载浏览器实际支持的那一种编码
- **`prefers-reduced-motion`**:油灯闪烁、粒子、开场 CG 全部停掉。
  画面里已经没有任何漂移可关了——机位本来就是钉死的

## 打开网址就能玩:它到底开不开得起来

这个项目最值得吹的一句话是**打开链接几秒钟就能玩**,而视频基座正是最容易
悄悄把它拿走的东西:素材一个一个长大,而测试的人网都快。
[`VIDEO.md`](../VIDEO.md) 第七节写了预算,也写了不要靠自觉:
**超了就判失败,不靠自觉**。之前没有任何东西在查。查了以后是这样的:

| | 之前 | 现在 |
|---|---|---|
| 慢 4G(3 Mbps)首帧 | 4788ms | **1009ms** |
| 慢 4G 片头放完 | 12.9 秒里放了 7.4 秒,卡 7 次 | **放完,0 次卡顿** |
| 3G(1.6 Mbps)首帧 | 8934ms | **1793ms** |
| 3G 片头放完 | 12.9 秒里放了 3.5 秒,卡 7 次 | **放完,卡 1 次** |
| 3G 到片头结束的流量 | — | **1.54 MB**(预算 2 MB) |

**瓶颈是网,不是 CPU。** 这一点是先量出来才动手的:主线程 **93.9% 空闲**,
特效层的每帧函数在 10057ms 里只占 12ms,把 CPU 降速到 **6 倍**之后
rAF 仍然跑 **60.1fps**、最差帧间隔 17ms。所以这一轮一行渲染代码都没有优化。

三件事:

1. **片头有了自己的码率上限。** 牌桌片段和片头受限于不同的东西:片段是画质受限的
   ——它们贴在一张 JPEG 底板上、上面有黑蕾丝,CRF 28 是蕾丝不烂掉的那条线;
   片头是网络受限的,它是 12 秒的片子而观众正盯着它没有别的可看。
   所以 `TIERS` 表里每个输出带自己的码率,片段继续用 `-b:v 0`(纯画质、无上限),
   片头给了上限。`intro.webm` **6087 → 2451 KB**(3.78 → 1.56 Mbps),
   `intro.mp4` 2339 → 866 KB。画面没有动:识别闸门在这段真帧上打的分从 3.40 变成 3.43(限 5)。
   H.264 的上限要靠 `-maxrate` + `-bufsize`,光给 `-crf` 是不管用的。
2. **每段片子之前都下载了两遍。** `prefetch.ts` 用 `<link rel="prefetch" as="video">`
   预取六段片子,而预取**不带 Range 头**、`<video>` 元素要的是 `Range: bytes=0-`,
   前者的缓存项满足不了后者。实测待机片 276 KB 付了两次、natural 片 162 KB 两次,
   合计约 1 MB,而且全都在跟当时正在放的片子抢带宽。视频预取整个删掉了
   ——`<video preload>` 本来就会把 Range 处理对。底板图还留着,它们是普通图片、
   是片段播不出来时的兜底,但**改成了片头放完之后才预热**:
   四张全幅 JPEG 约 650 KB,压在片头前面会让它在 3 Mbps 上卡四次,
   而这些字节十三秒之后才用得上。
3. **网速细就发小档。** 之前小档只看屏幕宽度,于是 3G 上的手机拿小档、
   同样 3G 上的笔记本拿大档——偏偏笔记本才是那个要吞 3.78 Mbps 的。
   宽度是"屏幕小"的好代理、是"管子细"的坏代理。浏览器自己知道是哪一种:
   `navigator.connection` 会报有效连接等级和用户有没有要求省流量,
   `thinConnection()`(`src/platform.ts`)读它。Safari / Firefox 上没有这个 API,
   答案是 false、拿大档——这恰好是对的,因为它们的兜底是 H.264,
   而片头的 H.264 本来就是两种编码里小的那个。

`verify-weight.mjs` 是守这件事的闸门,它**在限速下跑两遍**,
并且顺便断言细网那条路真的拿到了 `.sm` 文件,免得预算因为走错路而通过。

两个坑写在这里,免得下一个人再踩:**resource timing 量不了流媒体**
——响应没结束之前 `encodedBodySize` 一直是 0,而正在串流的 `<video>` 永远不会结束,
所以字节数是从 CDP 的 `Network.dataReceived` 累出来的(第一版量出 0.10 MB 这种胡话就是这个原因)。
另外 **CDP 的限速不会改 `navigator.connection`**,所以连接等级得注入桩才能走到细网那条路。

## 已验证 / 未验证

**已经验证可用:**

- 引擎 **30 项测试**,含 `describe.each(RULE_ORDER)` 驱动的**每张桌子 120 局全自动模拟**,
  断言筹码守恒到个位、每局必然终局、任何状态下都存在合法操作
- **发牌就是从牌靴前面照顺序发**有测试(40 组种子):你拿到的是第 1、3 张,
  她拿到的是第 2、4 张(**交替发**,不是先发完你再发她),
  而且记牌数正好等于台面上这四张牌的和
- **配乐不泄露真相**有测试:三度颜色随 `shown` 变,换 `truth` 不动
- **片头与牌桌是同一版人物、同一套衣服**有测量(`scripts/verify-identity.mjs`),
  线上取帧打分,并直接比较**线上片头与线上牌桌的服装区**(不需要参考文件,
  所以不可能靠"两边一起错"通过)
- **服装钉死**有两道断言:成片级(`verify-costume.mjs`,`build-clips` 会强制跑)
  与片段级(`verify-clip-costume.mjs`,量的是逐帧位移)
- **五种窗口尺寸 × 三个阶段**的边缘体检(`scripts/verify-edges.mjs`),没有元素掉出画面
- **她在动、而房间不动**有两道测量。`verify-motion.mjs`:关掉颗粒层后
  她的脸的变化是静态控制条的 **24 倍**,而背后的酒架只有她的脸的 **21%**(限 40%)。
  **一开始这个脚本是错的**——它量整帧,而颗粒层每帧重绘整个屏幕,
  于是"99% 的帧在变化"既是真的又什么都没说明;
  后来它又**错在要求酒架也动**,而那条只有机位漂移能满足(见上)。
  `verify-still.mjs` 是精确的那一道:合成页面上六个背景块,**位移全部 0px**
- 浏览器**长时段实测**(`scripts/playthrough.mjs`):桌面 40 手、iPhone 14 视口 14 手、
  单副牌桌 16 手(其中洗牌 2 次),**每一手都核对台面报的净额与筹码实际变动一致**,
  逐步做布局体检(按钮有没有掉出视口、有没有矮于 40px、有没有横向滚动),零 console 错误
- **无缓存新访客实测**线上地址:片头在放(`currentTime` 真的在走)、
  能进选桌页、桌上的片段有画面且在走、发得出四张牌、一手能结算、能开下一手,零坏响应
- **限速下开得起来**有断言(`verify-weight.mjs`):3G 上首帧 1793ms、
  到片头结束 **1.54 MB**(预算 2 MB)、片头放完;慢 4G 上首帧 1009ms、零卡顿。
  字节数从 CDP 累的,不是从 resource timing 读的(后者对流媒体恒为 0)
- **键盘有可见焦点、结果会被读出来**:每个控件 Tab 到都有 2px 金色描边
  (`:focus-visible`,**用 `el.focus()` 是测不出来的**,只有真的按 Tab 才触发),
  结果走一个常驻的屏幕外 `role="status"` 节点、旁白行是 `aria-live="polite"`,
  `<html lang>` 跟着语言开关走。牌会**按语言念出名字**
  (`7 of clubs` / `8 de diamantes`,之前念的是 `7 of H`),
  暗牌念的是"face down / boca abajo",不泄底
- `tsc`、`oxlint`、`vitest` 全绿

**明确还没做:**

- 片段是生成的,不是真拍或真渲染的。**她的手始终没有离开台布**:
  试过四次让她真的去碰牌,模型要么凭空变出一副牌再把它化掉、
  要么把手指熔进牌靴的木头里、要么抬肩把滑落的肩带带上去(那会同时挂掉造型锁和循环闭合)。
  根源是那张源照片里没有东西可以给一只手拿。所以发牌与洗牌改成了**神情的拍子**
  ——她的目光跟着牌走、她讨一个换靴的空档——牌还是 DOM 画上去的
- **还是没有做过真人听感评审。** 配乐现在有可听的 wav 产物和三项数值断言
  (节奏密度、亮度、电平),但"热烈"最终是主观的:能测出每秒 6.2 个节奏事件、
  质心 1981 Hz,测不出它是不是好听。发行前仍应安排一次真人试听。
- **她的台词依赖平台语音。** 系统里没装对应语言的语音时只有哼音,没有词;
  自己合成可辨识的语音需要另一套工程(共振峰序列或音素拼接),这一版没做
- **"测得到"不等于"看得出"。** 现在她的脸是静态控制条的 24 倍,
  待机片里有两口呼吸和两次眨眼,逐帧量出来 749 对相邻帧里 **638 对在动**
  (中位步长 1.12,完全相同的只有 16 对)。
  但**先后有三次独立的视频复核把构建报告成"她完全静止"**,
  最近一次甚至报告她的首饰在变——逐帧复核否掉了它,几乎肯定是采样太稀。
  这一版还没有做过真人现场复核
- 她只有一位,人格是参数化的(`bluffRate`),不是学习型
- 没有服务端、没有存档、没有跨桌的继承(`SERIES.md` 里那份镇志还没做)
- 横屏手机只做到"不坏",没有为它单独排版
- 光照曲线还没有烤(`BLACKJACK.md` 第四节那条:从视频逐帧抽亮度去驱动 DOM)。
  现在油灯闪烁是程序化的随机,不是从片子里量出来的
- **无障碍只验到了可访问性树,没有用真的读屏软件走一遍。**
  焦点描边、live region、`<html lang>`、牌的名字都是量过的,
  但"NVDA / VoiceOver 里这一手听起来是什么样"没有人听过

## 合规提醒

当前实现是**纯娱乐模拟,不涉及任何真实货币**。一旦接入真实货币投注,
它就是受监管的博彩产品,需要牌照、KYC、地域限制和经过认证的随机数发生器。
那是法务与合规问题,不是工程问题。

牌面是原创设计——那个年代的牌背并不都在公有领域。
角色设定上她是**这张桌子的主人**,不是奖品;衣着是时代正确的赌馆女庄家,
没有越线内容(理由与发行后果见 `BLACKJACK.md` 第六节)。

### 脚本

```bash
node scripts/build-clips.mjs              # 关键帧 → 光流 → 缓动重采样 → VP9 / H.264
node scripts/playthrough.mjs [url] [n]    # 长时段实测:账目、布局、报错
node scripts/verify-edges.mjs [url]       # 五种窗口尺寸 × 三个阶段,有没有东西掉出画面
node scripts/verify-motion.mjs [url]      # 她到底有没有在动 / 背景有没有跟着一起动
node scripts/verify-still.mjs [url]       # 机位锁死:合成后的页面上,背景一个像素都不许位移
node scripts/verify-generated.mjs [mp4…]  # 生成片段能不能用:首帧、闭环、肩带、房间、机位、她活着
node scripts/verify-identity.mjs <url> <ref.jpg> [old.jpg]   # 片头与桌上是同一版人物、同一套衣服
node scripts/lock-costume.mjs [--check]   # 整幅画面钉到主成片上,只放行各帧该贡献的部分
node scripts/verify-costume.mjs           # 每张成片穿的是不是同一套(build-clips 会自动跑)
node scripts/verify-clip-costume.mjs      # 服装在片段内部有没有在动
node scripts/verify-seam.mjs              # 合成缝:她的手臂钉住了没有、边界上有没有硬边
node scripts/verify-smoothness.mjs [url]  # 打三手 × 三遍,量掉帧 / 帧间隔 / 画面有没有瞬间空掉
node scripts/verify-weight.mjs [url]      # 限速下跑两遍:首帧多久、片头放不放得完、首屏几个字节
node scripts/render-score.mjs [outdir] [url]   # 把真实音频图录成 wav,配乐可以打开来听
node scripts/verify-audio.mjs [url]       # 节奏密度 / 亮度 / 电平的断言,以及她到底说没说话
node scripts/verify-deploy.mjs <url>      # 把部署好的站当无缓存新访客走一遍
node scripts/shots.mjs [outdir] [url]     # 各视口各语言截图
node scripts/record-demo.mjs [url] [dir]  # 录页面本身(不是录屏)
```

`record-demo.mjs` 录的是**页面**而不是屏幕,这一条是有代价换来的:
桌面录屏会把长会话压缩,于是 120ms 的眨眼变成零帧、6.9 秒的呼吸循环读起来就是一张照片。
**本项目实测过这个坑**——外部视频复核两次报告"她完全是静止的",
而同一段录像逐帧量出来是 **99% 的帧在变化**(均值 0.83 luma、峰值 12.5 那一下是眨眼)。
次秒级的东西一律以 ffmpeg 逐帧数据为准,不以观感为准。

`verify-identity.mjs` 是 [`VIDEO.md`](../VIDEO.md) 第六节要求的那道防线:
视频基座有一类别的脚本都看不见的失败——素材都加载了、片段都在播、布局也干净,
但**人变了**,或者半个构建还在用旧素材。换造型、重出成片正是这种事最容易发生的时候。
它从线上片头和线上牌桌各取一帧,分别和新旧参考成片打分,断言**离新的明显更近**。
换造型那次实测:

```
intro_look   vs current   1.07   vs previous  21.95
intro_title  vs current   7.58   vs previous  22.27
table        vs current   8.42   vs previous  22.21
```

`verify-edges.mjs` 的存在也是因为一次具体的失败:控制条写死了高度,内容长过了它,
于是在 1280×720 上键位提示和离桌链接被底边切掉一半——而在 1440×900 上完全看不出来,
偏偏那是当时唯一在看的尺寸。

后来它又加了一条**重叠**断言(任何两个带数字的元素不许相交),而这条断言一上线就
连抓出四件事:结果横幅印在手牌点数上、每手的注额撞上金额行、
1920 宽下金额数字压在牌上(**这条一直存在,只是在 `.card` 被纳入检查之前看不见**)、
以及押注阶段多出来的筹码行让控制条比其它阶段更高、溢出到台布上。
布局因此改了三处:注额并进标签行、筹码并进操作行、控制条高度改成
`clamp(120px, 19vh, 146px)` 跟着视口**高度**缩放(640px 高的窗口要用少三分之一的空间
塞下同样的东西),牌的尺寸也从只看宽度改成 `min(3.7vw, 6.4vh)`。

**提示文字也从画面顶端搬到了底部那一行**:她在新造型里在画面里更大,
顶端的提示会印在她额头上,长句换行还会压到眼睛——而人物是这一版最该被看清的东西。
现在底部那一行按优先级显示:旁白 > 常驻的那句提示,一个槽位,不占额外高度。

**结果横幅最后落在台布左侧筹码旁边那片空绿呢上。** 居中压在画面上时,
没有任何一个高度能在所有窗口尺寸下同时躲开庄家和手牌标签;
塞进控制条又要吃掉它没有的 29px。那个角落是真的空着。

除 `build-clips.mjs` 之外都需要先跑起 `npm run dev`(或给一个线上地址)。

### 闸门自己也会错,而且错得比它守的东西更贵

这一版里三道闸门是**被当成缺陷修掉的**,因为一个会随机失败、或者失败信息是假的闸门,
比没有闸门更糟:它会教人忽略红色。

- **`verify-motion.mjs` 断言的是相反的东西。** 它要求酒架和她的脸动得一样多,
  而满足这条的只有机位漂移那个缺陷本身(详见上文"机位是钉死的")。
- **`verify-audio.mjs` 里抄了一份台词表,而抄的那份过期了。**
  `'Let's see, then.'` 是拿掉出千那次加进 `LINES.deal` 的,没有同步到闸门里;
  `'mírame'` 则是被删掉的叫牌台词留下的。于是**四次发牌里会随机挂一次**,
  而失败信息写着"发牌的时候她什么都没说"——正上方的逐条记录里明明写着她说了。
  现在断言的是**说的时机**而不是词:发牌点击后 2.5 秒内必须有一句
  (牌的落点最晚 700ms,所以这个窗口宽裕又不会把后面的话算进来)。
  改台词改不坏它。
- **`verify-identity.mjs` 给一张没到的黑帧打了分。** 它 seek 到固定时间点再截图,
  但监听的是 `seeked`——那只说明解码器动了,不说明有一帧交到了合成器手里。
  机器一忙,2500ms 的兜底超时就在什么都没画出来的时候触发。
  接着算术把这件事藏了起来:**一张黑图和真图的差,约等于真图自己的平均亮度**,
  于是它报出"片头和牌桌的服装不一样(31.67)"——一个长得跟真换了衣服一模一样的数字。
  现在 seek 等的是 `requestVideoFrameCallback`(而且在 seek 开始**之前**就挂好,
  否则那一帧可能在回调注册之前就已经上屏),并且**空白样本本身就是一条失败**,
  不再是比较的输入。空白的阈值是 **26 而不是 0**:`signalstats` 读的是有限范围亮度,
  纯黑量出来是 16.00,按 0 写的检查永远不会触发——这一条差点就那么写了。

`verify-smoothness.mjs` 的丢帧率则改成了**三遍取中位数**。它曾经以 5.07% 挂在 4% 的线上,
而在同一个构建上连跑三遍是 4.02% / 3.31% / 2.41%;
剖出来主线程 93.9% 空闲、CPU 降速 6 倍仍有 60.1fps,所以量到的是机器忙不是代码慢。
取中位数而不是取三遍里最好的那一遍:**取最好的会把真的回归藏掉**,
中位数遇到真回归会动、遇到一次被抢的采样不会动。另外三项指标仍然按最差那一遍算
——那三项里出现一次坏瞬间,本来就该判失败。三遍的数都打出来,
下一个看到它变红的人能分清是抖动还是位移。

## 代码结构

```
src/
  game/
    types.ts       房规表(RULES)、阶段机、发牌的时序常量
    engine.ts      纯函数:发牌、要牌/停牌/加倍/分牌、算牌、结算、pressure()
    ai.ts          她的人格、对结算的反应、shown 与 truth 的分离(她会摆脸色)
    engine.test.ts
  cards/
    Card.tsx       52 张牌面 + 牌背,程序化 SVG
  components/
    Scene.tsx      分层画面:.camera(钉死的机位)、成片、闭眼孪生帧、非对称溶解、视频层;以及牌靴读数
    Clip.tsx       视频层本身:待机片当常亮底床、动作片叠在上面淡入、手机档选源
    Intro.tsx      开场 CG:按比例定位的双语字幕、跳过、进度条
    SoundToggle.tsx
  fx/
    Atmosphere.tsx Canvas 颗粒、烟、暗角。**盖在 UI 之上**,不只盖视频
  audio/
    engine.ts      WebAudio 图、卷积混响、ducking、钢琴总线的门控、录音抽头
    score.ts       norteño 乐队、oom-pah、rasgueado、大小调绑 shown、洗牌接缝、片头卡点
    voice.ts       她的声音:自合成哼音 + 平台语音的发牌与报点
    sfx.ts         牌、筹码、牌靴、洗牌
  i18n/strings.ts  en(事实来源)+ es-MX,漏翻编译不过
  art.ts           成片 / 片段 / poster 的 URL,统一过 BASE_URL
  platform.ts      窄屏、触屏、减少动态效果三个媒体查询
  App.tsx          片头 / 标题页 / 选桌页 / 牌桌,回合编排与镜头节奏

clipsrc/
  *.jpg            片头专用的关键帧
  openart/         她那六段生成片段的源文件 + 生成方法(见该目录的 README)
public/
  art/             她的全幅状态成片(含只差一口呼吸与只差眼睑的两张孪生帧)
  clips/           构建产物:7 段 × 2 尺寸 × 2 编码 + poster
```

两条值得记住的结构约束:

- **`engine.ts` 是纯函数,不碰 React,也不含任何字符串。** 前者让它能被大量模拟测试覆盖,
  后者让本地化不必穿透游戏规则。规则差异全部收敛到 `RULES` 那张表上。
- **游戏状态的权威副本存在 ref 里,React state 只作渲染镜像。**
  回合编排是异步的(要等片段播完),不能依赖重渲染的时序;
  她由每次玩家操作后显式 `await` 驱动,而不是靠 effect——
  后者会在"锁释放但状态没变"时死锁。

还有第三条,是这一款独有的:

- **视频永远不是权威时钟。** 牌什么时候落到台面上只看引擎侧的 `performance.now()`;
  片子卡住、提前播完或倍速改变,都不会把牌局的时序挪走。
  **片段是画面,不是规则。**

- **机位不许出现在样式表里。** 包住所有图层的那个元素永远不带 transform,
  由 `verify-still.mjs` 在真实页面上守着。她的动作属于片段文件,
  房间的静止属于机位,两件事不在同一个地方实现。
