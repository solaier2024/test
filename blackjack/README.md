# DEALER'S CHOICE · LA CASA MANDA

一张 1884 年美墨边境赌馆的二十一点桌。对面坐着一位发牌的女庄家,
她会做手脚,而你可以抓她。

**纯娱乐模拟,不涉及任何真实货币、不设投注、不发奖金。**
标题页与选桌页都明示了这一点。

角色造型:吊带缎面束腰、黑蕾丝长手套、天鹅绒 choker,暖金烛光下的边境赌馆荷官。
**桌上与片头用的是同一批成片**(同机位、同造型),所以不会出现"片头一套、桌上一套"。

实现的是本仓库 [`BLACKJACK.md`](../BLACKJACK.md) 与
[`OPENING_AND_SCORE.md`](../OPENING_AND_SCORE.md) 两份方案;
系列定位见 [`SERIES.md`](../SERIES.md),视频基座路线见 [`VIDEO.md`](../VIDEO.md)。

## 玩法

直上二十一点是一道被算死的数学题,基本策略表一查决策就没了。
所以这一桌真正在赌的不是牌面:

> **你赌的是"她这一手干净吗"。**

三层叠起来:

### 1. 算牌(基础层)

Hi-Lo。**读数不是 HUD 上的数字,是牌靴里剩下的厚度**——
真实的算牌人就是看这个。左侧那条竖读数就是牌靴,金边越亮表示这副牌越偏向你。

### 2. 抓千(核心层)

她有三种手法:**发第二张**(把好牌留给自己、差牌推给你)、
**偷看底牌**(于是她补牌补得比规则更聪明)、**换冷牌**(洗牌时塞一摞排好的)。

破绽是**手上的一下微光**,而规则是一条可以练出来的知觉规律:

> **真破绽发生在牌还在她手里的时候;牌落到桌上之后的小动作,一律是假的。**

- **凑近看(按住 LEAN IN / 按住 L)**:破绽的持续时间更长、更明显。
  代价是你的视线离开了牌靴(左侧读数会暗下去),而且**她会注意到**(热度上升)。
- **叫破(CALL HER / C)**:对了,这一局归你、她的信誉掉一格、房间凉一点;
  错了,赔掉这一局的注,而且她有了你的分寸。

**这不是掷骰子。** 破绽是老实渲染出来的:她真的做了手脚,那一下就真的在那儿。
判定跑的是引擎自己的时钟(`performance.now()`)而不是视频进度,
所以片子卡一下不会把你瞄准的那个窗口挪走。

**而且她出千只改牌的顺序,不改牌的内容**——所以算牌的人永远不会被算术骗,
只会被她的手骗。这条有一项测试专门守着它。

### 3. 房规(第三层)

`LA CASA MANDA` 那张桌子上,**她可以随时改一条规则,但要先付钱进底池**
(这一局不许加倍 / 这一局黑杰克平赔 / 这一局不许分牌)。
价钱明写在台面上。于是她不是一台执行规则的机器。

### 热度

被怀疑不是单向的。**你越盯她,房间越盯你**;热度满了,穿好外套的人请你出去。
但**房间会忘事**:安静坐着热度会退下去。没有这条衰减,四次叫错就得走人,
而那样就不是一张能坐一小时的桌子了。

### 三张桌子

| | 牌副数 | 软 17 | 黑杰克 | 她能改规则 | 底注 |
| --- | --- | --- | --- | --- | --- |
| **ONE DECK** | 1 | 停 | 3:2 | 否 | 10 |
| **LA CASA MANDA** | 6 | 补 | 3:2 | **能,每次付钱** | 15 |
| **SIX TO FIVE** | 6 | 补 | **6:5** | 否 | 10 |

**牌副数越少,算牌越有用,她做手脚的动机就越强**,所以这三档不只是难度,
是三种不同的博弈重心。规则全部收敛在 `src/game/types.ts` 的 `RULES` 一张表上,
加一张桌子是改配置不是改逻辑。

### 键盘

`H` 要牌 · `S` 停牌 · `D` 加倍 · `P` 分牌 · **按住 `L`** 凑近看 ·
`C` 叫破 · `空格` 继续

长按对一部分玩家不可行,所以 LEAN IN **点一下也能切换**,两种输入在规则上完全等价。

## 画面:她是视频,牌是合成上去的

二十一点有 52 张牌、任意手数、要牌/加倍/分牌。**不可能为每种牌面拍视频。**
所以这一桌的架构是:

```
实时特效层   颗粒、暗角、烟、油灯闪、热度色偏     ← 响应引擎状态,逐帧
牌 / 筹码 / UI(DOM + SVG)                    ← 贴在台布平面上
视频层       她的动作片段                        ← 播完即撤,失败即隐身
兜底成片层   每段视频的首尾帧本身                ← 首屏方案 + 弱网方案
```

### 为什么这张桌子做得起

**她的动作词汇和牌面是正交的。** 不管牌是什么,她只会做这些事——
于是一整局二十一点只要 **7 段短片**:

| 片段 | 帧数 | 时长 | 何时播 |
| --- | --- | --- | --- |
| `idle` | 206 | 6.87s | 桌面空闲时循环:**全程在呼吸**,眨眼落在里面,无缝接回 |
| `deal` | 23 | 0.77s | 发牌。手伸到最远的那一帧正是牌落桌的时刻 |
| `warm` / `sharp` / `cool` | 24 / 20 / 16 | 0.53–0.80s | 她的神色变了 |
| `shuffle` | 35 | 1.17s | 切牌卡出现。**这一段同时是配乐换乐段的接缝** |
| `caught` | 27 | 0.90s | 被你抓到。不走溶解,是硬切 |
| `intro` | 366 | 12.20s | 开场 CG,六个镜头 |

**每段片子的首尾帧本身就是一张成片**,所以静止姿态是一个星形图的中心:
N 段而不是 N² 段,任何两个动作之间都通过底下那张成片接上,不会跳帧。

### 不需要 alpha 合成

一旦她的手要盖在牌上,就需要带透明通道的视频,而 alpha 视频在 Web 上很麻烦。
**这个需求是被设计掉的,不是用技术硬扛的:**

| 状态 | 怎么做 | 需要 alpha? |
| --- | --- | --- |
| 静止 | 她是不带 alpha 的循环视频,牌是 DOM,两者在画面上不重叠 | 不需要 |
| 发牌的 0.77 秒 | **全幅视频占满画面**,牌在她手里看不清身份;动作末帧牌落定,这时 DOM 牌元素出现 | 不需要 |

**"用运动把身份问题藏进去"**,于是 95% 的画面完全不需要合成,
而看到的是一双真手把牌发到桌上。

### 牌是画出来的,不是拍的

52 张牌面是程序化 SVG(`src/cards/Card.tsx`)。**这是三件事同时的答案**:
向量在任何尺寸都锐利、不需要和底下的成片连戏、
而且牌面是**原创**的——那个年代的牌背设计并不都在公有领域。

### 光流流水线

所有成片都是**同机位**渲染的,两张只差一个动作的图正是稠密光流要的输入:

```
关键帧对 → ffmpeg minterpolate 稠密光流 → 按缓动曲线重采样 → VP9 / H.264 双尺寸 + poster
```

```bash
node scripts/build-clips.mjs          # 全部
node scripts/build-clips.mjs deal     # 只重建某几段
node scripts/build-clips.mjs intro    # 只重建片头
FORCE=1 node scripts/build-clips.mjs  # 忽略缓存
```

需要 `ffmpeg` 与 `ffprobe`。产物已提交,只有改了关键帧才要重跑。
稠密形变缓存在 `node_modules/.clipcache/`,**所以只调时序的重建是秒级的**——
光流每对关键帧只算一次 48 步,之后所有时序都是在那条曲线上按缓动重采样。

三个坑,代码里都留了注释守着:

- **`minterpolate` 会丢掉首尾两个区间。** 直接喂两张图出来 0 帧。
  输入必须垫成 `[a, b, b]`,才恰好剩一个区间、输出 `steps+1` 帧。
- **image2 解复用器认扩展名不认字节。** 一张 JPEG 改名成 `.png` 会被静默丢弃,
  片子悄悄变短还不报错。所以每帧先过 `normalised()`,并在编码后断言帧数一致。
- **光流很贵,改时序不该重跑它。** 见上面的缓存。

## 开场 CG

12.2 秒六个镜头,全程暖金烛光(**不是**冷蓝的纪录片调,也不是左轮对决那种肃杀):

1. 雨后的巷子,坎蒂纳门口泼出来的暖光铺在湿石板上——这是一句邀请,不是一座荒镇
2. 穿过赌馆:法罗的台布、骰笼、吧台边笑着的人,房间是活的
3. 她低头看牌 → **抬眼看你**
4. **微距:她戴蕾丝手套的手在切牌,而且留了一张牌在掌下。** 虚焦背景里是她的红缎胸衣
   和天鹅绒 choker,所以这双手是谁的没有疑问
5. 一张牌、一杯酒、一把空着的椅子——全片唯一直接对玩家说话的一镜
6. 她的一个笑,片名压上

镜间 0.4 秒 `xfade` 叠化,首尾各一次淡入淡出。

**第 4 镜是教学镜,而且它现在把"千"本身画进去了。** 它和第 5 句台词
—— *"The cards are clean. Nobody ever said she was."* ——
一起把"要盯她的手"这件事教掉,而 **clean / limpias 就是玩法里的词**,
所以进桌之后不需要任何教程。

字幕**按片长的比例定位**而不是按秒数(`Intro.tsx` 的 `CUES`),
所以重剪片头不会把台词甩到错误的镜头上。中途切语言立刻换轨。

只播一次(`localStorage`),标题页留了一个 **WATCH THE OPENING / VER LA APERTURA**
随时重看。点画面任意处、空格 / 回车 / Esc、或右下角 SKIP 都能跳过,**第一帧就能跳**。
开了"减少动态效果"偏好的人直接跳过,不播。

## 配乐:一支坎蒂纳里的北墨乐队

**全部 WebAudio 运行时合成,一个音频文件都没有**,也没有用任何外部音包——
所以没有需要署名的第三方素材,也不存在授权风险。

第一版是钉在一个和弦上的哈巴涅拉。纸面上讲得通,做出来像酒店大堂。
**边境午夜的坎蒂纳不是氛围铺底,是角落里一支吵到你得凑近说话的乐队。**
所以现在是 **norteño**:

| | |
| --- | --- |
| 速度 | **116 bpm** 的 polka 感(旧版 72,这是它听起来客气的最大原因) |
| 骨架 | Bajo sexto 的 **oom-pah**:正拍根音、二拍五音,永不停 |
| 反拍 | **手风琴和弦戳** + **吉他 rasgueado 扫弦**同时打在反拍上 |
| 和声 | `i – i – iv – V7`(D),**真的在走**,不再是一个不动的低音 |
| 节奏乐器 | Palmas、claves、tambora,**往前提**而不是闷在混响里 |
| 混响 | 节奏组的 room send 从 0.34 降到 **0.11** |
| 旋律 | 手风琴主奏,牌靴对你有利时**下方叠一个三度**——这套风格的招牌平行三度 |
| 彩头 | 赢钱时来一声 **grito**(角落里有人吼那一下) |

### 三度仍然绑她"表现出来"的情绪

这条原则没动,只是**升级了**:以前是一个音在 F(174.61 Hz)和 F♯(185.00 Hz)
之间翻;现在是**整个主和弦在 D 小调和 D 大调之间翻**。
绑的仍然是 `readDealer()` 返回的 `shown`,**永远不绑 `truth`**——
所以配乐依然是她表演的一部分,和她的脸一样可靠,也就是一样不可靠。
有测试断言换 `truth` 不动配乐。

### 洗牌仍然是乐句的接缝

她每次洗牌播一段**真的离开主调**的过门(V of V 进属和弦,北墨乐队示意下一段的写法),
回来时换乐句。所以听觉上的循环远长于写出来的四小节,**而每次重置都有画面上的理由**。

### 可听可测

`scripts/render-score.mjs` 把**真实音频图**(`MediaStreamDestination` 挂在 master 上,
不是为测试另写一份编排)录成 wav,所以配乐是能打开来听的:

```
title          onsets/s   4.4   centroid  1420 Hz   rms  -32.7 dBFS   peak -13.0 dBFS
table_cold     onsets/s   6.0   centroid  1885 Hz   rms  -30.2 dBFS   peak -12.7 dBFS
table_hot      onsets/s   6.2   centroid  1981 Hz   rms  -28.2 dBFS   peak -11.8 dBFS
shuffle_seam   onsets/s   6.0   centroid  1960 Hz   rms  -27.4 dBFS   peak  -8.8 dBFS
opening        onsets/s   7.3   centroid  1970 Hz   rms  -26.5 dBFS   peak  -9.8 dBFS
```

`scripts/verify-audio.mjs` 把这三个量变成断言:**每秒 ≥5 个节奏事件**(热烈)、
**频谱质心 ≥1700 Hz**(手风琴和掌击在前面而不是在混响后面)、
**电平 ≥−32 dBFS 且不削顶**,外加一条"满编排必须比薄编排更响",
否则那三个情绪旋钮就没在干活。"听起来更热烈"不可测,但**让它听起来更热烈的那些东西都是数字**。

### 混音:叫破的时候隔壁的钢琴停了

| 事件 | 压多少 | 保持 | 释放 |
| --- | --- | --- | --- |
| 翻牌 | −8% | 0.12s | 0.5s |
| 推筹码 | −6% | 0.10s | 0.4s |
| **叫破** | **−95%** | **0.6s** | 1.6s |

**而且叫破那一下,隔壁的钢琴直接停,六秒内不回来。** 这是这个类型最老的一个手势,
而它几乎不要钱——钢琴本来就是单独一条总线。

## 她的声音:发牌与报点

两层,单独任何一层都不够。

### 1. 哼音(coo),自己合成的

三个失谐锯齿过两组元音共振峰(760 / 1320 Hz),音高**先微降再往上挑 240 音分**,
外加一层带通气声和一段迟到的浅颤音。**往上挑那一下就是"嗲"的来源**——
平的听起来是无聊,往下掉听起来是失望。

它是 WebAudio,所以和别的东西一样过房间混响、一样被 ducking 压、一样被静音掐掉,
**而且永远可用**。

### 2. 台词,走平台语音合成

免费、无需署名、没有音频文件。关键是这一对参数:

```
pitch 1.75    rate 0.9    volume 0.72
```

**高音高配慢语速,才是又软又撩;同样的词用默认参数念出来是火车报站。**
音量 0.72 是故意压在乐队之下——她是在音乐里说话,不是在播报。

哼音先响,台词晚 180ms 跟上,所以句子开始之前那个气口已经在了。

### 覆盖的节点

| 时机 | 例(en / es-MX) |
| --- | --- |
| 入座 | *Sit down, darling. Place your bet.* / *Siéntate, mi vida. Pon tu apuesta.* |
| **发牌** | *Cards, sugar.* / *Cartas, mi vida.*(四句轮换) |
| 要牌 | 只有哼音,不说话——这一下触发最频繁,说话会腻 |
| **报点(你)** | *nineteen* / *diecinueve* |
| **报点(庄家揭牌)** | *house has twenty* / *la casa, veinte* |
| 洗牌 | *A fresh deck, just for you.* / *Baraja nueva, sólo para ti.* |
| Blackjack / Bust / 赢 / 输 / 平 | 各有专句 |
| 抓到她 | *Mm. How did you see that?* / *¿Cómo lo viste?* |
| 叫错 | *Nothing there, sweetheart.* / *Ahí no había nada, corazón.* |

中英西里主轨跟随现有的双语开关(`en` / `es-MX`),说的是哪一种就挑哪一种系统语音,
优先墨西哥/美西女声。节流是 650–900ms,所以句子不会叠在一起。

**静音开关一并静音。** 语音合成不在 WebAudio 里,所以 ducking 管不到它,
只能设音量并在静音时显式 `cancel()`——两件都做了。

### 怎么验

**平台语音在无头浏览器里通常是没有的**,所以 `verify-audio.mjs` 不去录声音,
而是在页面里挂住 `speechSynthesis.speak`,断言**游戏在该说话的时候要了正确的词**。
实测一手牌:

```
"Sit down, darling. Place your bet."  pitch 1.75  rate 0.9  volume 0.72  en-US
"Cards, sugar."                      pitch 1.75  rate 0.9  volume 0.72  en-US
"four"                               pitch 1.75  rate 0.9  volume 0.72  en-US
"house has twenty"                   pitch 1.75  rate 0.9  volume 0.72  en-US
"Mine, I'm afraid."                  pitch 1.75  rate 0.9  volume 0.72  en-US
```

断言里也包含参数本身:pitch < 1.4 就不是她,rate > 1 太赶,volume > 0.85 会坐在音乐上面。

**注意 `render-score.mjs` 录出来的 wav 里没有台词**——语音合成是平台服务,
不经过 WebAudio,录不到;wav 里有的是它底下那层哼音。

## 移动端

竖屏不是把桌面版缩小,是另一套排法:`object-fit: cover` 把 16:9 的成片塞进
390×844 只能看见约四分之一的画面宽度。所以竖屏把屏幕切成**明确的分带**:

```
0    – 44dvh   舞台(她)
26   – 44dvh   牌(压在舞台下半部,也就是桌面上)
45   – 50dvh   读数条(牌靴横放、热度)
50   – 54dvh   提示行
54   – 100dvh  操作区
```

用 `dvh` 而不是 `vh`,地址栏收起时不会把底部按钮顶出屏幕。其它几件事:

- **`hover` 全部关进 `@media (hover: hover)`。** 触屏上 hover 会"粘住",
  另外补了一组 `:active` 反馈
- **安全区**:`viewport-fit=cover` + `env(safe-area-inset-*)`,画面铺到刘海底下,控件不进去
- **所有按钮 ≥50px 高**(离桌那个链接 44px)
- **手机档片源**:`(max-width: 860px)` 时自动取 `.sm` 版本,
  并且只预取浏览器实际支持的那一种编码
- **`prefers-reduced-motion`**:镜头呼吸、油灯闪烁、粒子、开场 CG 全部停掉

## 已验证 / 未验证

**已经验证可用:**

- 引擎 **37 项测试**,含 `describe.each(RULE_ORDER)` 驱动的**每张桌子 120 局全自动模拟**,
  断言筹码守恒到个位、每局必然终局、任何状态下都存在合法操作
- **"出千只改顺序、不改内容"**这条公平性质有专门的测试(40 组种子),
  断言出千后牌靴 + 桌面的牌 id 集合与开局完全一致,而且记牌数对得上
- **破绽时序**有测试:真破绽必然早于牌落桌,诱饵必然晚于牌落桌(各 300 次)
- **配乐不泄露真相**有测试:三度颜色随 `shown` 变,换 `truth` 不动
- **片头与牌桌是同一版人物**有测量(`scripts/verify-identity.mjs`),线上取帧打分
- **五种窗口尺寸 × 三个阶段**的边缘体检(`scripts/verify-edges.mjs`),没有元素掉出画面
- **画面在动**有专门的测量(`scripts/verify-motion.mjs`):关掉颗粒层后
  画面区域的变化是静态控制条的 18 倍。
  **一开始这个脚本是错的**——它量整帧,而颗粒层每帧重绘整个屏幕,
  于是"99% 的帧在变化"既是真的又什么都没说明
- 浏览器**长时段实测**(`scripts/playthrough.mjs`):桌面 30 手、iPhone 14 视口 14 手、
  单副牌桌 16 手(其中洗牌 2 次),**每一手都核对台面报的净额与筹码实际变动一致**,
  逐步做布局体检(按钮有没有掉出视口、有没有矮于 40px、有没有横向滚动),零 console 错误
- **无缓存新访客实测**线上地址:片头在放(`currentTime` 真的在走)、
  能进选桌页、桌上的片段有画面且在走、发得出四张牌、一手能结算、能开下一手,零坏响应
- `tsc`、`oxlint`、`vitest` 全绿

**明确还没做:**

- 片段是光流合成的,不是真拍或真渲染的。大动作(转身、起立)超出两张关键帧能插出来的范围
- **还是没有做过真人听感评审。** 配乐现在有可听的 wav 产物和三项数值断言
  (节奏密度、亮度、电平),但"热烈"最终是主观的:能测出每秒 6.2 个节奏事件、
  质心 1981 Hz,测不出它是不是好听。发行前仍应安排一次真人试听。
- **她的台词依赖平台语音。** 系统里没装对应语言的语音时只有哼音,没有词;
  自己合成可辨识的语音需要另一套工程(共振峰序列或音素拼接),这一版没做
- **待机的动态偏轻。** `verify-motion.mjs` 量出画面的变化是静态控制条基准的 **18 倍**
  (关掉颗粒层之后,她的脸与背后的酒柜各 8.4 / 8.3 mean luma,控制条 0.46),
  所以动态确实在那儿——但那是"测得到"而不是"看得出":
  **两次独立的视频复核都把同一个构建报告成"她完全静止"。**
  已经把共享的镜头呼吸从 3px / 1% 提到约 6px / 1.6%,因为整幅画面的移动比胸口起伏好读得多;
  真要更明显还是得上更大的动作,而那超出两张关键帧能插出来的范围
- 她只有一位,人格是参数化的(`bluffRate` / `tellRate` / `nerve` / `attention`),不是学习型
- 冷牌(`cold`)在引擎里实现并测试了,但洗牌时还没有对应的专属破绽窗口,
  所以现在抓不到它——能抓的是发第二张与偷看底牌
- 没有服务端、没有存档、没有跨桌的热度继承(`SERIES.md` 里那份镇志还没做)
- 横屏手机只做到"不坏",没有为它单独排版
- 光照曲线还没有烤(`BLACKJACK.md` 第四节那条:从视频逐帧抽亮度去驱动 DOM)。
  现在油灯闪烁是程序化的随机,不是从片子里量出来的

## 合规提醒

当前实现是**纯娱乐模拟,不涉及任何真实货币**。一旦接入真实货币投注,
它就是受监管的博彩产品,需要牌照、KYC、地域限制和经过认证的随机数发生器。
那是法务与合规问题,不是工程问题。

牌面是原创设计——那个年代的牌背并不都在公有领域。
角色设定上她是**这张桌子的主人**,不是奖品;衣着是时代正确的赌馆女庄家,

### 脚本

```bash
node scripts/build-clips.mjs              # 关键帧 → 光流 → 缓动重采样 → VP9 / H.264
node scripts/playthrough.mjs [url] [n]    # 长时段实测:账目、布局、报错
node scripts/verify-edges.mjs [url]       # 五种窗口尺寸 × 三个阶段,有没有东西掉出画面
node scripts/verify-motion.mjs [url]      # 画面到底有没有在动(关掉颗粒层,拿静态控制条当基准)
node scripts/verify-identity.mjs <url> <ref.jpg> [old.jpg]   # 片头里的人和桌上的人是不是同一版
node scripts/render-score.mjs [outdir] [url]   # 把真实音频图录成 wav,配乐可以打开来听
node scripts/verify-audio.mjs [url]       # 节奏密度 / 亮度 / 电平的断言,以及她到底说没说话
node scripts/verify-deploy.mjs <url>      # 把部署好的站当无缓存新访客走一遍
node scripts/shots.mjs [outdir] [url]     # 各视口各语言截图
node scripts/record-demo.mjs [url] [dir]  # 录页面本身(不是录屏)
```

`record-demo.mjs` 录的是**页面**而不是屏幕,这一条是有代价换来的:
桌面录屏会把长会话压缩,于是 120ms 的眨眼变成零帧、6.9 秒的呼吸循环读起来就是一张照片。
**本项目实测过这个坑**——外部视频复核两次报告"她完全是静止的",
而同一段录像逐帧量出来是 **99% 的帧在变化**(均值 0.83 luma、峰值 12.5 那一下是眨眼)。
次秒级的东西一律以 ffmpeg 逐帧数据为准,不以观感为准。

`verify-identity.mjs` 是 [`VIDEO.md`](../VIDEO.md) 第六节要求的那道防线:
视频基座有一类别的脚本都看不见的失败——素材都加载了、片段都在播、布局也干净,
但**人变了**,或者半个构建还在用旧素材。换造型、重出成片正是这种事最容易发生的时候。
它从线上片头和线上牌桌各取一帧,分别和新旧参考成片打分,断言**离新的明显更近**。
换造型那次实测:

```
intro_look   vs current   1.07   vs previous  21.95
intro_title  vs current   7.58   vs previous  22.27
table        vs current   8.42   vs previous  22.21
```

`verify-edges.mjs` 的存在也是因为一次具体的失败:控制条写死了高度,内容长过了它,
于是在 1280×720 上键位提示和离桌链接被底边切掉一半——而在 1440×900 上完全看不出来,
偏偏那是当时唯一在看的尺寸。

后来它又加了一条**重叠**断言(任何两个带数字的元素不许相交),而这条断言一上线就
连抓出四件事:结果横幅印在手牌点数上、每手的注额撞上金额行、
1920 宽下金额数字压在牌上(**这条一直存在,只是在 `.card` 被纳入检查之前看不见**)、
以及押注阶段多出来的筹码行让控制条比其它阶段更高、溢出到台布上。
布局因此改了三处:注额并进标签行、筹码并进操作行、控制条高度改成
`clamp(120px, 19vh, 146px)` 跟着视口**高度**缩放(640px 高的窗口要用少三分之一的空间
塞下同样的东西),牌的尺寸也从只看宽度改成 `min(3.7vw, 6.4vh)`。

**结果横幅最后落在台布左侧筹码旁边那片空绿呢上。** 居中压在画面上时,
没有任何一个高度能在所有窗口尺寸下同时躲开庄家和手牌标签;
塞进控制条又要吃掉它没有的 29px。那个角落是真的空着。

除 `build-clips.mjs` 之外都需要先跑起 `npm run dev`(或给一个线上地址)。

## 代码结构

```
src/
  game/
    types.ts       房规表(RULES)、阶段机、破绽的时序常量
    engine.ts      纯函数:发牌、要牌/停牌/加倍/分牌、算牌、抓千、结算、热度
    ai.ts          她的人格、什么时候出千、shown 与 truth 的分离
    engine.test.ts
  cards/
    Card.tsx       52 张牌面 + 牌背,程序化 SVG
  components/
    Scene.tsx      分层画面:成片、闭眼孪生帧、非对称溶解、视频层、破绽微光;以及牌靴读数
    Clip.tsx       视频层本身:poster 兜底、失败即隐身、手机档选源
    Intro.tsx      开场 CG:按比例定位的双语字幕、跳过、进度条
    SoundToggle.tsx
  fx/
    Atmosphere.tsx Canvas 颗粒、烟、暗角。**盖在 UI 之上**,不只盖视频
  audio/
    engine.ts      WebAudio 图、卷积混响、ducking、钢琴总线的门控、录音抽头
    score.ts       norteño 乐队、oom-pah、rasgueado、大小调绑 shown、洗牌接缝、片头卡点
    voice.ts       她的声音:自合成哼音 + 平台语音的发牌与报点
    sfx.ts         牌、筹码、牌靴、洗牌、破绽的耳语、叫破
  i18n/strings.ts  en(事实来源)+ es-MX,漏翻编译不过
  art.ts           成片 / 片段 / poster 的 URL,统一过 BASE_URL
  platform.ts      窄屏、触屏、减少动态效果三个媒体查询
  App.tsx          片头 / 标题页 / 选桌页 / 牌桌,回合编排与镜头节奏

clipsrc/           片头专用的关键帧
public/
  art/             她的全幅状态成片(8 张,含只差一口呼吸与只差眼睑的两张孪生帧)
  clips/           构建产物:7 段 × 2 尺寸 × 2 编码 + poster
```

两条值得记住的结构约束:

- **`engine.ts` 是纯函数,不碰 React,也不含任何字符串。** 前者让它能被大量模拟测试覆盖,
  后者让本地化不必穿透游戏规则。规则差异全部收敛到 `RULES` 那张表上。
- **游戏状态的权威副本存在 ref 里,React state 只作渲染镜像。**
  回合编排是异步的(要等片段播完),不能依赖重渲染的时序;
  她由每次玩家操作后显式 `await` 驱动,而不是靠 effect——
  后者会在"锁释放但状态没变"时死锁。

还有第三条,是这一款独有的:

- **视频永远不是权威时钟。** 抓千的判定窗口只看引擎侧的 `performance.now()`;
  片子卡住、提前播完或倍速改变,都不会把玩家瞄准的那个窗口挪走。
  **片段是画面,不是规则。**
